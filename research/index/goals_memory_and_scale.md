## Cut memory and bandwidth

Start with [Memory and cost](../topics/core_theory.md#memory-and-cost) and [Memory by domain](../topics/core_theory.md#memory-by-domain), then [Storage layouts](../topics/cascade_layout_and_merging.md#storage-layouts) and [Formats](../topics/cascade_layout_and_merging.md#formats).

- Fit world-space GI in memory for a bounded volume: Dense or clipmap grids of 32³ to 64³ fit; trade-off is memory scaling with volume. ([Dense and clipmap world grids](../topics/single_frame_3d_rc.md#dense-and-clipmap-world-grids), single_frame_3d_rc)
- Keep dense world grids within Vulkan's 128 MiB buffer limit: Dense world grid split across buffers; trade-off is splitting and extra bookkeeping. ([Budgets for single-frame 3D RC (derived)](../topics/performance.md#budgets-for-single-frame-3d-rc-derived), performance)
- Predict world grid memory from its probe count: Dense grid storage law; trade-off is padded layouts can multiply allocation by six. ([Memory per unit (derived)](../topics/performance.md#memory-per-unit-derived), performance)
- Shrink dense 3D grid memory without full grids: Clipmapped and voxel-volume designs; trade-off is bookkeeping and random reads cost time. ([What the numbers show](../topics/performance.md#what-the-numbers-show), performance)
- Cut the memory of 3D cascades: Cascade −1 gathering removes stored cascade 0; costs per-pixel tracing at gather. ([Memory by domain](../topics/core_theory.md#memory-by-domain), core_theory)
- Remove stored cascade 0 to save memory in 3D: Cascade −1 replaces cascade 0 storage; trade-off is a per-pixel gather. ([Cascade −1 and contact detail](../topics/cascade_layout_and_merging.md#cascade-1-and-contact-detail), cascade_layout_and_merging)
- Hold only two cascades in memory at once: Ping-pong textures reused for each cascade; trade-off is each cascade depends on the one above. ([Containers](../topics/cascade_layout_and_merging.md#containers), cascade_layout_and_merging)
- Cut RC bandwidth by storing radiance in smaller formats: R11G11B10F and RG16F targets; trade-off is precision lost when merged values are re-stored. ([Formats](../topics/cascade_layout_and_merging.md#formats), cascade_layout_and_merging)
- Cut merge texture reads from four probes to one: One hardware fetch with pre-averaging; trade-off is direction-first storage and tile clamping. ([Merge kernels](../topics/cascade_layout_and_merging.md#merge-kernels), cascade_layout_and_merging)
- Use one filtered fetch per lower ray with contiguous reads: Direction-first layout with pre-averaging; trade-off is no measured speedup in GM Shaders. ([Position-first and direction-first](../topics/cascade_layout_and_merging.md#position-first-and-direction-first), cascade_layout_and_merging)
- Cut cascade memory and merge lookups fourfold: Store four-ray means; trade-off is a weaker parallax fix and off-target bilinear rays. ([Pre-averaging](../topics/cascade_layout_and_merging.md#pre-averaging), cascade_layout_and_merging)
- Keep only two cascades live during the merge: Fused top-down schedule; trade-off is tracing cannot overlap merging. ([Tracing and merging order](../topics/cascade_layout_and_merging.md#tracing-and-merging-order), cascade_layout_and_merging)
- Keep 3D cascade memory within a GPU budget: Constant-memory layout keeps 3D memory bounded; trade-off: loses HRC's sharp transverse resolution. ([3D](../topics/holographic_rc.md#3d), holographic_rc)
- Store light fields compactly: Vector quantization of 4D tiles; trade-off: artifacts appear above about 200:1. ([Background: light fields and line space](../topics/holographic_rc.md#background-light-fields-and-line-space), holographic_rc)
- Store only occupied blocks of line space: Blocks of line-indexed texels built from 2x2 children; trade-off: unweighted sums, unfinished. ([Block cascades](../topics/holographic_rc.md#block-cascades), holographic_rc)
- Keep cascade memory constant as the grid grows: Interval count stays constant per cascade; trade-off: directions double per level. ([Geometry](../topics/holographic_rc.md#geometry), holographic_rc)
- Store point-light falloff with few cascades: Gradient storage per direction; trade-off: occlusion still aliases. ([Gradient RC](../topics/holographic_rc.md#gradient-rc), holographic_rc)
- Extend HRC to 3D without N⁴ memory: Frusta only where occluders are, or sparse polygonal blocks; trade-off: unsolved extensions in 3D. ([Open questions](../topics/holographic_rc.md#open-questions), holographic_rc)
- Fit HRC in a real-time frame budget: Write fewer bytes per pass: one transmittance channel, fewer probes; trade-off: no coloured glass. ([Performance](../topics/holographic_rc.md#performance), holographic_rc)
- Cut colour cost in HRC: Luminance and colour split; trade-off: colour bleeds at k-pixel resolution. ([jason.today/hrc](../topics/holographic_rc_implementations.md#jasontodayhrc), holographic_rc_implementations)
- Store spectral cascades in few transmittance bins: Transmittance in few bins, radiance in Fourier moments; trade-off: merge accuracy unverified. ([Open questions](../topics/volumetric_and_radiative_transfer.md#open-questions), volumetric_and_radiative_transfer)
- Store HDR radiance in few bits without filtering: R11G11B10F; trade-off: no sign or alpha, so transmittance needs its own 16-bit channel. ([Storage and colour](../topics/volumetric_and_radiative_transfer.md#storage-and-colour), volumetric_and_radiative_transfer)
- Save cascade textures by updating six images in place: In-place updates need no ping-pong, but reads mix old and new values. ([Godot](../topics/2d_implementations.md#godot), 2d_implementations)
- Cut RC memory without losing much quality; Fit a 2D RC game into a handheld memory budget: 2x/3x branching: cheaper than 2x/4x, 2.75× cascade 0 memory. ([Setups that worked in 2D](../topics/2d_implementations.md#setups-that-worked-in-2d), 2d_implementations)
- Store cascades so texel reads follow access order: Direction-first layout: optimized build ~2.3× faster per pixel (derived); builds also differ. ([GM Shaders (Yaazarai and Xor)](../topics/2d_articles_and_demos_gm_shaders.md#gm-shaders-yaazarai-and-xor), 2d_articles_and_demos_gm_shaders)
- Cut the storage wasted on occluded probes: Store sparse intervals with a bitmap; trade-off: extra indirection in the merge. ([Other sparse designs](../topics/3d_world_space.md#other-sparse-designs), 3d_world_space)
- Cut the memory of 3D cascades: Store only probes near visible surfaces; trade-off: placement and hashing complexity. ([Why sparse](../topics/3d_world_space.md#why-sparse), 3d_world_space)
- Catch off-screen emitters without a 3D probe grid's memory: Probes stay on the depth buffer; intervals traced in world space; trade-off is slow rays. ([Screen probes with world intervals](../topics/3d_screen_space.md#screen-probes-with-world-intervals), 3d_screen_space)
- Cut cascade VRAM without changing the merge layout: Pre-averaging; trade-off is that the thesis measured no comparison without it. ([Dell'Ova (2025): performance scaling with DXR](../topics/3d_screen_space_theses.md#dellova-2025-performance-scaling-with-dxr), 3d_screen_space_theses)
- Estimate SPWI storage at a chosen screen resolution: Cells × directions × levels table; counts entries, so totals need 16 bytes each. ([tmpvar's storage calculator](../topics/3d_screen_space_implementations.md#tmpvars-storage-calculator), 3d_screen_space_implementations)
- Pack every cascade's probes and intervals into one fixed-size texture: Probe blocks in a 2048-squared cache; every cascade gets the same texel budget. ([Cascade layout and intervals](../topics/3d_surface_probes.md#cascade-layout-and-intervals), 3d_surface_probes)
- Cut the memory of 3D cascades: Pre-averaging over 4 directions; memory above cascade 0 drops to about a quarter, losing detail. ([Cascades and probes](../topics/3d_surface_probes.md#cascades-and-probes), 3d_surface_probes)
- Size surfel cascades to a memory budget: Per-cascade divide-by-4 probes and times-4 intervals; coarse cascades get fewer probes. ([Parameters](../topics/3d_surface_probes.md#parameters), 3d_surface_probes)
- Predict how much memory a surfel cascade needs: Equal-texel radiance textures dominate; fewer surfels save little memory. ([Surfel storage](../topics/3d_surface_probes.md#surfel-storage), 3d_surface_probes)
- Hold a 3D cascade hierarchy in one probe grid's memory: Halving-texel grids; trade-off: space and direction are coupled, so resolution is fixed by range. ([Cascades](../topics/rc_for_sampling_and_guiding_rcpg.md#cascades), rc_for_sampling_and_guiding_rcpg)
- Cut the bandwidth of cascade gathering: Nearest-neighbour lookups; trade-off: visible edges at noise level, which denoisers or ReSTIR hide. ([Implementation and bandwidth](../topics/rc_for_sampling_and_guiding_rcpg.md#implementation-and-bandwidth), rc_for_sampling_and_guiding_rcpg)
- Scale guiding to larger worlds without wasted memory: Proposed sparse octree or hash; trade-off: unbuilt, though 90% of memory sits idle. ([Limits and future work](../topics/rc_for_sampling_and_guiding_rcpg.md#limits-and-future-work), rc_for_sampling_and_guiding_rcpg)
- Stream a sparse voxel octree on demand from ray requests: Ray requests fetch bricks as needed; a 128 MB cache gives 5.9% misses. ([GigaVoxels: sparse voxel octrees with ray-guided streaming](../topics/scene_representation_and_tracing_voxels_and_bvhs.md#gigavoxels-sparse-voxel-octrees-with-ray-guided-streaming), scene_representation_and_tracing_voxels_and_bvhs)
- Cache voxel radiance in sparse clipmaps within memory limits: Sparse bricks reach 500 m on PC with 128 bits per voxel, 64 on mobile. ([HSGI's sparse voxel cache](../topics/scene_representation_and_tracing_voxels_and_bvhs.md#hsgis-sparse-voxel-cache), scene_representation_and_tracing_voxels_and_bvhs)
- Budget the memory of cascaded GI volumes: Cascade geometry and texture table; trade-off: about 164 MiB at four cascades before history. ([SDFGI, the shipped GI](../topics/godot_integration.md#sdfgi-the-shipped-gi), godot_integration)
- Predict whether a larger dense grid fits in memory: Storage per base probe and the 128 MiB buffer limit; derived figures, not measured. ([Derived points](../topics/godot_projects.md#derived-points), godot_projects)
- Fit large-world probe grids into memory: 0.5 m grid at about 1 KB visibility per probe; 1 m spacing showed artifacts. ([Chen's Monter probes](../topics/related_probe_gi.md#chens-monter-probes), related_probe_gi)
- Store probe irradiance in little memory: R11G11B10F and 8×8 maps: about 1,696 bytes per probe; 8-bit formats show artifacts. ([DDGI](../topics/related_probe_gi.md#ddgi), related_probe_gi)
- Keep voxel octree memory bounded for large scenes: Sparse octree with anisotropic voxels at 1.5 times the memory; about 1024 MB for Sponza. ([Voxel cone tracing](../topics/related_probe_gi.md#voxel-cone-tracing), related_probe_gi)
- Cache indirect light in hashed cells with bounded memory: Hash grid of 40-byte entries, 160 MiB baseline; capped history and stale-frame eviction bound it. ([SHaRC](../topics/related_radiance_caches.md#sharc), related_radiance_caches)
- Keep 3D caustic memory bounded: Adaptive topology splitting cleaned a sphere but used too much memory. ([Caustics and refraction](../topics/light_transport_alternatives.md#caustics-and-refraction), light_transport_alternatives)
- Render huge voxel scenes within a fixed GPU memory budget: Streams requested nodes only; trade-off: the rasterizer must ask for nodes first. ([Other work on Sannikov's channel](../topics/history_and_landscape.md#other-work-on-sannikovs-channel), history_and_landscape)
- Use world-space RC within a memory budget: Caps world-space cascades at three or four; trade-off: closer to SSGI than Lumen. ([Positions on 3D RC](../topics/history_and_landscape.md#positions-on-3d-rc), history_and_landscape)
- Represent lighting lobes compactly with closed-form integrals: Spherical Gaussians; trade-off: each lobe approximates rather than matching exactly. ([Spherical Gaussians](../topics/supporting_techniques.md#spherical-gaussians), supporting_techniques)
- Compress distant irradiance into nine coefficients: Spherical harmonics bands 0–2; trade-off: about 1% error, low-frequency lighting only. ([Spherical harmonics](../topics/supporting_techniques.md#spherical-harmonics), supporting_techniques)
- Shrink mesh assets for download with little visible loss: Draco quantizes positions and codes connectivity; trade-off: fewer position bits mean lower quality. ([Draco](../topics/supporting_techniques_structures_and_tracing.md#draco), supporting_techniques_structures_and_tracing)
- Keep spatially close grid cells close in memory: Morton bit-interleaved keys preserve locality; trade-off: bit-spreading cost per lookup. ([Morton order](../topics/supporting_techniques_structures_and_tracing.md#morton-order), supporting_techniques_structures_and_tracing)
- Store large sparse volumes without a dense grid: VDB block tree stores only occupied blocks; trade-off: partly filled leaves waste memory. ([VDB and GVDB](../topics/supporting_techniques_structures_and_tracing.md#vdb-and-gvdb), supporting_techniques_structures_and_tracing)
- Store HDR radiance in 32 bits: Packs HDR colour into 32 bits; trade-off: no alpha, so transmittance needs another channel. ([R11G11B10F](../topics/supporting_techniques_transport_and_math.md#r11g11b10f), supporting_techniques_transport_and_math)
- Pack unit-range values into 32 bits with alpha: Ten-bit unorm channels; trade-off: values clamp to the 0 to 1 range. ([RGB10A2](../topics/supporting_techniques_transport_and_math.md#rgb10a2), supporting_techniques_transport_and_math)
- Store HDR probe radiance compactly in 32 bits: Shared exponent packs three channels; trade-off: small channels lose precision beside bright ones. ([RGB9E5](../topics/supporting_techniques_transport_and_math.md#rgb9e5), supporting_techniques_transport_and_math)

## Use GPU data structures and atomics

Start with [GPU data structures](../topics/supporting_techniques_structures_and_tracing.md#gpu-data-structures) in the glossary and [GPU building blocks](../topics/3d_world_space.md#gpu-building-blocks) for what carries to RenderingDevice. Atomics without float support are in [Float atomics](../topics/supporting_techniques_transport_and_math.md#float-atomics).

- Remove atomic contention from world-space deposits: Sort-based binning; trade-off is a sort step, 1.5 ms for 10 M texels. ([Open problems, ranked](../topics/single_frame_3d_rc.md#open-problems-ranked), single_frame_3d_rc)
- Build probe hash tables without slowdown at high load: Open addressing at twice probe count; trade-off: 7 to 9 times slower by 0.9 load. ([GPU building blocks](../topics/performance.md#gpu-building-blocks), performance)
- Cut Split RC's non-trace work without atomic deposits: Sort-based binning or per-probe tracing; trade-off is that neither is measured yet. ([Open questions](../topics/performance.md#open-questions), performance)
- Keep a GPU hash table lock-free without resizing: Keys never move and CAS inserts need no locks; trade-off: fixed capacity, slow high-load inserts. ([A simple lock-free GPU hash table](../topics/3d_world_space.md#a-simple-lock-free-gpu-hash-table), 3d_world_space)
- Sort GPU keys without relying on forward progress: ForwardSweep recomputes stalled predecessors; trade-off: histogram rework and unmodified predecessor keys. ([GPUSorting](../topics/3d_world_space.md#gpusorting), 3d_world_space)
- Store world-space probes in a GPU hash table: Hash probes with linear probing at low load; trade-off: memory for short probe chains. ([Hash maps for probes](../topics/3d_world_space.md#hash-maps-for-probes), 3d_world_space)
- Look up and insert keys in a GPU hash map: Cooperative 4-thread probing; gains only at high load, plain probing best at low load. ([Parallel hash maps (cuCollections)](../topics/3d_world_space.md#parallel-hash-maps-cucollections), 3d_world_space)
- Accumulate radiance without 64-bit atomics: Fixed-point u32 atomicAdd accumulators; trade-off: radiance clamped at 16 before storing. ([Data layout](../topics/3d_world_space_implementations.md#data-layout), 3d_world_space_implementations)
- Choose a key width and accumulator format for a port: Table of five codes on keys, LODs, probes, accumulators and history; no speed comparison. ([How the Split RC codes differ](../topics/3d_world_space_implementations.md#how-the-split-rc-codes-differ), 3d_world_space_implementations)
- Build the probe set on the GPU without CPU readback: Retry queues and prefix passes place probes; trade-off: failed inserts retry up to 31 times. ([Passes](../topics/3d_world_space_implementations.md#passes), 3d_world_space_implementations)
- Assign each ray hit to the cascade matching its distance: Log-base-4 cascade choice with transparent deposits below; hits fill every lower cascade. ([Split deposit](../topics/3d_world_space_implementations.md#split-deposit), 3d_world_space_implementations)
- Find the surfels near a point without searching neighbouring cells: One bucket read per query; hash collisions return distant surfels that need filtering. ([Hash grid (`shared/hash.slang`)](../topics/3d_surface_probes.md#hash-grid-sharedhashslang), 3d_surface_probes)
- Share light between path vertices without a neighbour search; Evict stale cache entries with one atomic operation: Quantized hash key averages vertices; leaks across voxels, and no motion vectors are needed. ([Path space filtering](../topics/related_radiance_caches.md#path-space-filtering), related_radiance_caches)
- Write HDR sweep results without float atomics: Two-pass accumulation; memory grows with directions times samples. ([Berhard's sweep framework](../topics/light_transport_alternatives.md#berhards-sweep-framework), light_transport_alternatives)
- Hash table keys with simple integer mixing: Jenkins one-at-a-time hash; trade-off: processes input byte by byte. ([Jenkins hashes](../topics/supporting_techniques.md#jenkins-hashes), supporting_techniques)
- Generate per-probe random numbers on the GPU cheaply: PCG-based GPU hash; trade-off: stateless 32-bit hash, not a random stream. ([PCG and GPU hashes](../topics/supporting_techniques.md#pcg-and-gpu-hashes), supporting_techniques)
- Hash probe and surfel keys quickly without cryptographic strength: xxHash32; trade-off: non-cryptographic, so unsuited to security. ([xxHash32](../topics/supporting_techniques.md#xxhash32), supporting_techniques)
- Store sparse radiance cells in a GPU hash table: Hashed keys address sparse cells; trade-off: collisions and eviction cost rise with load. ([GPU hash tables](../topics/supporting_techniques_structures_and_tracing.md#gpu-hash-tables), supporting_techniques_structures_and_tracing)
- Compact and allocate GPU output in parallel without extra passes: Single-pass look-back scan allocates output; trade-off: tile status synchronization and memory traffic. ([Prefix sums and decoupled look-back](../topics/supporting_techniques_structures_and_tracing.md#prefix-sums-and-decoupled-look-back), supporting_techniques_structures_and_tracing)
- Sort rays, probes or BVH primitives on the GPU: Onesweep runs one pass per digit; trade-off: integer keys only. ([Radix sort and Onesweep](../topics/supporting_techniques_structures_and_tracing.md#radix-sort-and-onesweep), supporting_techniques_structures_and_tracing)
- Accumulate many splat contributions into a shared buffer: Integer atomicAdd on scaled sums; trade-off: fixed-point range and precision limits. ([Float atomics](../topics/supporting_techniques_transport_and_math.md#float-atomics), supporting_techniques_transport_and_math)
- Share values across threads without shared memory: Quad shuffles and ballots exchange in-register values; trade-off: only where the API exposes subgroups. ([Subgroup operations](../topics/supporting_techniques_transport_and_math.md#subgroup-operations), supporting_techniques_transport_and_math)

## Choose parameters

Start with [Parameters the evidence supports](../topics/single_frame_3d_rc.md#parameters-the-evidence-supports), then [Cascade scaling](../topics/core_theory.md#cascade-scaling), [Directions](../topics/cascade_layout_and_merging.md#directions), [Intervals](../topics/cascade_layout_and_merging.md#intervals) and [Cascade count](../topics/cascade_layout_and_merging.md#cascade-count).

- Choose cascade intervals that keep error even across scales; Set cascade 0 direction count without visible artifacts: Interval scaling ×4 per cascade; trade-off is relying on the derived equal-error law. ([Parameters the evidence supports](../topics/single_frame_3d_rc.md#parameters-the-evidence-supports), single_frame_3d_rc)
- Size probe spacing and directions from the smallest light: Penumbra condition sets spacing and angle; a sampling rule, not a cost measure. ([The penumbra condition](../topics/core_theory.md#the-penumbra-condition), core_theory)
- Keep angular error uniform across cascades: l = 4 interval scaling matches error per cascade; smallest resolvable light doubles per cascade. ([Two criteria for interval scaling (derived)](../topics/core_theory.md#two-criteria-for-interval-scaling-derived), core_theory)
- Choose cascade count so the top interval covers the diagonal; Let the top cascade reach the domain boundary: log4 of the diagonal sets the count; trade-off is one more cascade per 4× diagonal. ([Cascade count](../topics/cascade_layout_and_merging.md#cascade-count), cascade_layout_and_merging)
- Pick a 3D map that nests with equal solid angle; Cut axis bias in 3D octahedral maps at low resolution; Trace directions around one surface normal with hemisphere maps: Equal-area octahedral map nests with no per-texel weights; trade-off is an arctangent per lookup. ([Direction maps in 3D](../topics/cascade_layout_and_merging.md#direction-maps-in-3d), cascade_layout_and_merging)
- Tile each ray with contiguous intervals and no gaps; Keep cascade 0 starting at zero to cover near contact: Contiguous geometric ×4 starts at zero; trade-off is interval lengths grow 4× per cascade. ([Intervals](../topics/cascade_layout_and_merging.md#intervals), cascade_layout_and_merging)
- Find the best nested equal-area map at low direction counts; Choose irradiance tile size and placement for single-frame shading: Cylindrical and Clarberg maps; trade-off is that no comparison was published with metrics. ([Open questions](../topics/cascade_layout_and_merging.md#open-questions), cascade_layout_and_merging)
- Choose a 3D direction map that needs no per-texel weights; Use a contiguous geometric 3D interval family without overlap: Equal-area nested map; trade-off is the cylindrical versus Clarberg choice is unresolved. ([Single-frame assessment](../topics/cascade_layout_and_merging.md#single-frame-assessment), cascade_layout_and_merging)
- Run base-16 ray counts without artifacts: No tested fix; base-B scaling halves spatial ratio at base 16 per cascade. ([Base ray counts other than 4](../topics/artifacts_and_fixes.md#base-ray-counts-other-than-4), artifacts_and_fixes)
- Choose a direction spacing for 3D cube faces: Equal tangent, equal angle or equal area spacing; trade-off: cone-weight error against lookup cost. ([Open questions](../topics/holographic_rc.md#open-questions), holographic_rc)
- Choose per block between density and coverage averaging: Jensen-gap bound on structure orientation; trade-off: not yet tested. ([Open questions](../topics/volumetric_and_radiative_transfer.md#open-questions), volumetric_and_radiative_transfer)
- Size cascade textures for a non-square viewport: Square region of side max(W,H); trade-off: 43.75% of each cascade lies off screen. ([Otavio Peixoto, OPEngine](../topics/2d_articles_and_demos.md#otavio-peixoto-opengine), 2d_articles_and_demos)
- Pick the cascade level count from the screen size: Diagonal-stop level loop; trade-off: a non-integer target width (1820.44 texels). ([SimonDev's demo](../topics/2d_articles_and_demos.md#simondevs-demo), 2d_articles_and_demos)
- See how ray counts grow per cascade level: Branching factor B scales rays and radii per level; the demos show layout, not timing. ([tmpvar's playground](../topics/2d_articles_and_demos.md#tmpvars-playground), 2d_articles_and_demos)
- Choose the interval split between cascades: Interval split near 0.02 UV; trade-off: shadows shift in proportion to the split. ([Part 2: building RC](../topics/2d_articles_and_demos_jason_today.md#part-2-building-rc), 2d_articles_and_demos_jason_today)
- Afford interval scaling l = 4 with a marching tracer: Grow step length with interval using filtered proxies; trade-off: per-sample mip handling. ([Marching cost](../topics/3d_world_space.md#marching-cost), 3d_world_space)
- Size cascade intervals so penumbras resolve: Penumbra condition bounds interval spacing; trade-off: α sets how rays fall per cascade. ([anoptic-engine](../topics/3d_world_space_implementations.md#anoptic-engine), 3d_world_space_implementations)
- Assign each ray hit to the cascade matching its distance: Log-base-4 cascade choice with transparent deposits below; hits fill every lower cascade. ([Split deposit](../topics/3d_world_space_implementations.md#split-deposit), 3d_world_space_implementations)
- Pick a quality preset trading pixels for ray budget: Presets cap pixel count, so rays per frame scale with resolution; trade-off: lower detail. ([The live demo](../topics/3d_world_space_implementations.md#the-live-demo), 3d_world_space_implementations)
- Pick a cascade 0 direction count with low cosine-law error; Keep world ray density constant across cascades: Eight octant directions minimum; uniform cos-theta polar sampling; trade-off is ray count. ([Directions in 3D](../topics/3d_screen_space.md#directions-in-3d), 3d_screen_space)
- Keep interval length matched to probe spacing at any depth: Pixel-unit or depth-scaled intervals; world-unit intervals break the penumbra condition with depth. ([Interval units and view depth](../topics/3d_screen_space.md#interval-units-and-view-depth), 3d_screen_space)
- Find the interval growth rate that keeps SPWI stable: Compare 2× and ×4 growth by measurement; open how many cascades scene scale needs. ([Open questions](../topics/3d_screen_space.md#open-questions), 3d_screen_space)
- Choose probe spacing, direction count and interval length: Each code's row shows the trade: ray count rises as spacing shrinks or directions grow. ([Parameters across projects](../topics/3d_screen_space.md#parameters-across-projects), 3d_screen_space)
- Keep the parallax error bounded across cascades: Interval scaling l = 2*K^(1/m) meets three error arguments; off it, parallax doubles per cascade. ([Connections](../topics/rc_for_sampling_and_guiding.md#connections), rc_for_sampling_and_guiding)
- Pick a validation rate that trades leak against shadow-ray cost: Higher rho removes leak but adds 33 to 53% shadow rays and costs small-emitter recovery. ([Limits and design axes](../topics/rc_for_sampling_and_guiding_reservoir_cascades.md#limits-and-design-axes), rc_for_sampling_and_guiding_reservoir_cascades)
- Keep record spacing sensible near and far from the camera: Spacing in projected pixels: dense near the camera; ties the cache to the view. ([Fixes from production](../topics/related_radiance_caches.md#fixes-from-production), related_radiance_caches)
- Vary angular resolution with local field anisotropy: Adaptive angular resolution: up to 8× faster in a phantom at equal accuracy. ([Other uses](../topics/light_transport_alternatives.md#other-uses), light_transport_alternatives)
- Choose probe spacing from light size and distance: Penumbra condition sets spacing; far probes need more directions, near ones tighter spacing. ([SimonDev's video](../topics/history_and_landscape.md#simondevs-video), history_and_landscape)
- Pick probe density between many small and few large probes: Radiance cascades mix all probe scales; trade-off: the paper gives only asymptotic scaling. ([The paper](../topics/history_and_landscape.md#the-paper), history_and_landscape)
- Store six-face direction maps with nested cells per level: Cube map with face subdivision; trade-off: corner texels cover less solid angle. ([Cube maps and face subdivision](../topics/supporting_techniques.md#cube-maps-and-face-subdivision), supporting_techniques)
- Give every direction texel the same solid angle: Equal-area octahedral map; trade-off: a more complex mapping than the plain octahedral. ([Equal-area octahedral map (Clarberg)](../topics/supporting_techniques.md#equal-area-octahedral-map-clarberg), supporting_techniques)
- Build nested direction sets by splitting Platonic solid faces: Geodesic subdivision; trade-off: tetrahedral 4·4^c directions versus 6·4^c for cube. ([Geodesic and tetrahedral subdivision](../topics/supporting_techniques.md#geodesic-and-tetrahedral-subdivision), supporting_techniques)
- Compute the solid angle of a spherical triangle exactly: Girard's theorem; trade-off: needs all three angles. ([Girard's theorem](../topics/supporting_techniques.md#girards-theorem), supporting_techniques)
- Get equal-area directions that nest four per level: HEALPix; trade-off: cell count fixed at 12·4^k. ([HEALPix](../topics/supporting_techniques.md#healpix), supporting_techniques)
- Map a sphere to a plane while preserving area: Lambert cylindrical projection; trade-off: preserves area, distorts shape. ([Lambert cylindrical equal-area projection](../topics/supporting_techniques.md#lambert-cylindrical-equal-area-projection), supporting_techniques)
- Store environment directions in a rectangular map: Latitude-longitude map; trade-off: rows near poles need sin θ weighting. ([Latitude-longitude map](../topics/supporting_techniques.md#latitude-longitude-map), supporting_techniques)
- Store unit directions in a square texture with little distortion: Octahedral map; trade-off: face-centre texels cover about 5.2× the solid angle of vertex texels. ([Octahedral map](../topics/supporting_techniques.md#octahedral-map), supporting_techniques)
- Store sphere directions without a pole in two maps: Parabolic maps; trade-off: two textures, one per hemisphere. ([Parabolic maps](../topics/supporting_techniques.md#parabolic-maps), supporting_techniques)

## Cover large worlds

Start with [Hybrids: screen near field, world far field](../topics/single_frame_3d_rc.md#hybrids-screen-near-field-world-far-field) and [Placement and levels of detail](../topics/3d_world_space.md#placement-and-levels-of-detail). Clipmaps are in the glossary under [Clipmaps and toroidal addressing](../topics/supporting_techniques_structures_and_tracing.md#clipmaps-and-toroidal-addressing).

- Use world-space RC where screen-space RC fails: Screen near field over world far field; trade-off is hand-off tuning between representations. ([Hybrids: screen near field, world far field](../topics/single_frame_3d_rc.md#hybrids-screen-near-field-world-far-field), single_frame_3d_rc)
- Keep dense world grids within Vulkan's 128 MiB buffer limit: Dense world grid split across buffers; trade-off is splitting and extra bookkeeping. ([Budgets for single-frame 3D RC (derived)](../topics/performance.md#budgets-for-single-frame-3d-rc-derived), performance)
- Shrink dense 3D grid memory without full grids: Clipmapped and voxel-volume designs; trade-off is bookkeeping and random reads cost time. ([What the numbers show](../topics/performance.md#what-the-numbers-show), performance)
- Let the top cascade reach the domain boundary: Top cascade traced to domain exit; trade-off is coarse angles may miss the boundary. ([Cascade count](../topics/cascade_layout_and_merging.md#cascade-count), cascade_layout_and_merging)
- Keep probe size constant on screen as the camera moves: Scale probes to pixel footprint and blend LODs; trade-off: seams at level boundaries. ([Placement and levels of detail](../topics/3d_world_space.md#placement-and-levels-of-detail), 3d_world_space)
- Light large scenes with a clipmap of world probes: Distance-field clipmap of world probes; trade-off: far directions do not grow 4× per level. ([EggyStudio/3DEngine](../topics/3d_world_space_implementations.md#eggystudio3dengine), 3d_world_space_implementations)
- Get world-scale GI off screen while keeping detail up close: Screen probes near, world probes far; trade-off is seams at the handover. ([Hybrids](../topics/3d_screen_space.md#hybrids), 3d_screen_space)
- Scale guiding to larger worlds without wasted memory: Proposed sparse octree or hash; trade-off: unbuilt, though 90% of memory sits idle. ([Limits and future work](../topics/rc_for_sampling_and_guiding_rcpg.md#limits-and-future-work), rc_for_sampling_and_guiding_rcpg)
- Keep a camera-centred distance field cheap to update: Camera-following clipmaps snap and rebuild few cascades per frame; new geometry lags. ([Sphere tracing and cheaper fields](../topics/scene_representation_and_tracing.md#sphere-tracing-and-cheaper-fields), scene_representation_and_tracing)
- Cache voxel radiance in sparse clipmaps within memory limits: Sparse bricks reach 500 m on PC with 128 bits per voxel, 64 on mobile. ([HSGI's sparse voxel cache](../topics/scene_representation_and_tracing_voxels_and_bvhs.md#hsgis-sparse-voxel-cache), scene_representation_and_tracing_voxels_and_bvhs)
- Keep dynamic objects in a voxel clipmap each frame: Per-frame dynamic clipmap resolves overlaps with atomicMax; geometry thinner than a voxel still leaks. ([Voxel tracing measured for RC](../topics/scene_representation_and_tracing_voxels_and_bvhs.md#voxel-tracing-measured-for-rc), scene_representation_and_tracing_voxels_and_bvhs)
- Scroll cascades with the camera without full rebuilds: Cascade scrolling with dirty slabs; trade-off: a shift of 128 cells rebuilds the whole cascade. ([SDFGI, the shipped GI](../topics/godot_integration.md#sdfgi-the-shipped-gi), godot_integration)
- Fit large-world probe grids into memory: 0.5 m grid at about 1 KB visibility per probe; 1 m spacing showed artifacts. ([Chen's Monter probes](../topics/related_probe_gi.md#chens-monter-probes), related_probe_gi)
- Cover large scenes with probe volumes that fall off in density: Camera-following cascaded volumes; coarser cascades update less often. ([DDGI](../topics/related_probe_gi.md#ddgi), related_probe_gi)
- Reach far indirect light with nested coarse grids: Three nested 32³ grids; 8 iterations limit reach; cost is linear in iterations and cells. ([Light propagation volumes](../topics/related_probe_gi.md#light-propagation-volumes), related_probe_gi)
- Keep voxel octree memory bounded for large scenes: Sparse octree with anisotropic voxels at 1.5 times the memory; about 1024 MB for Sponza. ([Voxel cone tracing](../topics/related_probe_gi.md#voxel-cone-tracing), related_probe_gi)
- Keep indirect diffuse cheap across a large scene without leaks: Radiance's adaptive sampling and leak tests; bias from spacing limits and assumed reflectance. ([Radiance's practice](../topics/related_radiance_caches.md#radiances-practice), related_radiance_caches)
- Light large scenes with a camera-centred clipmap: Nested lit-voxel clipmap with ambient cubes; trade-off: bleeding where fill data is missing. ([daGI v1 in Enlisted (2019)](../topics/related_engine_gi.md#dagi-v1-in-enlisted-2019), related_engine_gi)
- Keep world probe GI cheap as the scene scrolls: Feedback-steered updates and scroll-in hand-off; trade-off: probes refresh about every 48 frames. ([Radiance grid](../topics/related_engine_gi.md#radiance-grid), related_engine_gi)
- Render huge voxel scenes within a fixed GPU memory budget; Draw many more objects without matching triangle growth: Streams requested nodes only; trade-off: the rasterizer must ask for nodes first. ([Other work on Sannikov's channel](../topics/history_and_landscape.md#other-work-on-sannikovs-channel), history_and_landscape)
- Pick probe detail by distance with fewer grid-alignment artifacts: Chebyshev-distance LOD steps per power of two; trade-off: coarse level changes. ([Chebyshev distance](../topics/supporting_techniques_structures_and_tracing.md#chebyshev-distance), supporting_techniques_structures_and_tracing)
- Keep camera-following probes and voxels cheap as the view moves: Clipmap windows rewrite only newly exposed strips; trade-off: fixed resolution per nested level. ([Clipmaps and toroidal addressing](../topics/supporting_techniques_structures_and_tracing.md#clipmaps-and-toroidal-addressing), supporting_techniques_structures_and_tracing)
- Draw very dense meshes without manual LOD authoring: Per-cluster LOD with streaming and visibility buffer; trade-off: needs engine-scale preprocessing. ([Nanite](../topics/supporting_techniques_structures_and_tracing.md#nanite), supporting_techniques_structures_and_tracing)
