Each section starts with where to begin, then lists every place in the topics that serves the goal, in reading order: the aim as the topic phrases it, how the section achieves it, and the link.

## Compute GI in one frame without history

Start with [What a single frame allows](../topics/single_frame_3d_rc.md#what-a-single-frame-allows) and [Where existing designs lean on time](../topics/single_frame_3d_rc.md#where-existing-designs-lean-on-time), then the [design families](../topics/single_frame_3d_rc.md#design-families). Every topic ends with a single-frame assessment, listed below.

- Compute GI each frame with no history or accumulation: Static geometry caches and deterministic probe sets only; trade-off is repeating deterministic errors. ([What a single frame allows](../topics/single_frame_3d_rc.md#what-a-single-frame-allows), single_frame_3d_rc)
- Remove temporal reuse from each replacement for a per-frame design; Keep a per-frame GI design free of history: Each history element has a same-frame replacement; trade-off is a known cost each. ([Where existing designs lean on time](../topics/single_frame_3d_rc.md#where-existing-designs-lean-on-time), single_frame_3d_rc)
- Run radiance cascades in 3D without temporal reuse: Deterministic probes with fixed ray counts; trade-off is cost paid entirely in rays. ([Why RC fits](../topics/single_frame_3d_rc.md#why-rc-fits), single_frame_3d_rc)
- Run single-frame world-space RC in real time: Split RC hashed probes near surfaces; trade-off is 8.6 ms relied on OptiX hardware RT. ([3D world space and surfaces](../topics/performance.md#3d-world-space-and-surfaces), performance)
- Fit single-frame 3D RC in a 4 ms budget: Screen probes at 4 to 8 px spacing; trade-off is fewer rays per pixel. ([Budgets for single-frame 3D RC (derived)](../topics/performance.md#budgets-for-single-frame-3d-rc-derived), performance)
- Compare single-frame RC with amortized GI at equal noise: Equal-noise ray counting; trade-off is amortized systems hide ray debt across frames. ([Connections](../topics/performance.md#connections), performance)
- Estimate a single-frame 3D RC budget under Godot's RenderingDevice: compute tracing at 1 to 3 G rays per second; trade-off is slower than hardware RT. ([Single-frame assessment](../topics/performance.md#single-frame-assessment), performance)
- Run 3D RC without temporal accumulation: K=4 with l=4 scaling; distant small lights alias more. ([Single-frame assessment](../topics/core_theory.md#single-frame-assessment), core_theory)
- Build a single-frame 3D RC with two live cascade buffers: Fused top-down pass; trade-off is N dependent dispatches with storage barriers. ([Single-frame assessment](../topics/cascade_layout_and_merging.md#single-frame-assessment), cascade_layout_and_merging)
- Split cascade work across two frames: Reduce Demand mode; trade-off is partial results are never shown. ([Tracing and merging order](../topics/cascade_layout_and_merging.md#tracing-and-merging-order), cascade_layout_and_merging)
- Remove one-frame lag in merged cascades: Per-cascade update rates; far cascades get more latency. ([Latency and flicker over frames](../topics/artifacts_and_fixes.md#latency-and-flicker-over-frames), artifacts_and_fixes)
- Build single-frame 3D RC without temporal accumulation: Hybrid low and high fixes; straight-ray fixes need cascade 0 bounds. ([Single-frame assessment](../topics/artifacts_and_fixes.md#single-frame-assessment), artifacts_and_fixes)
- Keep GI stable without temporal accumulation; Get multi-bounce light within one frame: Full solve each frame with no noise; trade-off: one extra full solve per bounce. ([Single-frame assessment](../topics/holographic_rc.md#single-frame-assessment), holographic_rc)
- Keep volumetric lighting inside a single-frame budget; Keep fog scattering single-frame except its in-scatter term: Bounded fog volume or screen-plane layout with mips; trade-off: full-scene grids do not fit. ([Single-frame assessment](../topics/volumetric_and_radiative_transfer.md#single-frame-assessment), volumetric_and_radiative_transfer)
- Run 2D GI from scratch each frame without temporal reuse; Get bounces without temporal feedback: Top-down single-frame cascades: 0.7–8.7 ms from 720p to 4K. ([Single-frame assessment](../topics/2d_implementations.md#single-frame-assessment), 2d_implementations)
- Run cascades without temporal history in one frame: Each demo recomputes cascades from scratch; temporal parts are optional; no measured costs. ([Single-frame assessment](../topics/2d_articles_and_demos.md#single-frame-assessment), 2d_articles_and_demos)
- Merge cascades within one Shadertoy frame: Cube-map packing or buffer rings; trade-off: several frames of lag before settling. ([How Shadertoy shapes the code](../topics/2d_shadertoys.md#how-shadertoy-shapes-the-code), 2d_shadertoys)
- Run the whole cascade chain in one frame: One pass per level reading the level above; trade-off: four rays per pixel per level. ([Independent codes](../topics/2d_shadertoys.md#independent-codes), 2d_shadertoys)
- Spread cascade levels over frames to save time: Even/odd level split; trade-off: the chain refreshes only every two frames. ([Media](../topics/2d_shadertoys.md#media), 2d_shadertoys)
- Decide which 2D parts transfer to single-frame 3D RC: Bilinear fix, C_MINUS1_GATHERING and per-level passes transfer; cube-map packing does not. ([Single-frame assessment](../topics/2d_shadertoys.md#single-frame-assessment), 2d_shadertoys)
- Cut single-frame noise at contact range: Larger probe footprints give more samples per cone; trade-off is spatial detail. ([Samples per direction per frame (derived)](../topics/3d_world_space.md#samples-per-direction-per-frame-derived), 3d_world_space)
- Keep GI stable without temporal accumulation: Bigger probes or more rays per pixel; trade-off: spatial detail or frame cost. ([Single-frame assessment](../topics/3d_world_space.md#single-frame-assessment), 3d_world_space)
- Run GI with no history so moving lights never lag: Per-frame recompute, as in jumeder and creikey; trade-off: 960 MiB and 126 M rays. ([Single-frame assessment](../topics/3d_world_space_implementations.md#single-frame-assessment), 3d_world_space_implementations)
- Get stable GI in a fast-moving game without temporal accumulation: PoE2 drops TAA and history; trade-off is screen-only light and a fixed top-down camera. ([Path of Exile 2](../topics/3d_screen_space.md#path-of-exile-2), 3d_screen_space)
- Build screen-space RC that needs no history: Placement-based fixes such as min/max probes; trade-off is that upper cascades still need more rays. ([Single-frame assessment](../topics/3d_screen_space.md#single-frame-assessment), 3d_screen_space)

- Stop screen-probe flicker without temporal reuse: Min+Max probes are the only measured fix; the thesis reports no stability figure. ([Single-frame assessment](../topics/3d_screen_space_theses.md#single-frame-assessment), 3d_screen_space_theses)
- Get single-frame GI on arbitrary meshes without hand-made UVs: Generated atlas probes on arbitrary meshes; indirect contact shadows below a texel are lost. ([A generated surface atlas (Blackline Interactive)](../topics/3d_surface_probes.md#a-generated-surface-atlas-blackline-interactive), 3d_surface_probes)
- Get 3D GI in one frame without history or denoiser: UV-chart probes merged top-down in one frame; needs UVs and chart seams. ([Single-frame assessment](../topics/3d_surface_probes.md#single-frame-assessment), 3d_surface_probes)
- Merge cascades in one frame instead of lagging a frame: Cross-fade each ray into its parent by hit distance; top-down merge removes the one-frame lag. ([X3XfRM (Mathis)](../topics/3d_surface_probes.md#x3xfrm-mathis), 3d_surface_probes)
- Cut single-frame noise at equal rays: The descent sampler over a merged cascade can importance-sample a near-field pass or specular rays from the same frame's cascades. ([Single-frame assessment](../topics/rc_for_sampling_and_guiding.md#single-frame-assessment), rc_for_sampling_and_guiding)
- Average world-space cascade texels within one frame: Cone or beam tracing of a prefiltered scene is suggested; brute force costs 37-58 ms. ([Single-frame assessment](../topics/rc_for_sampling_and_guiding.md#single-frame-assessment), rc_for_sampling_and_guiding)
- Estimate a single-frame equivalent of the moving average: Pre-averaging rays per texel; trade-off: brute force needs about 59 rays per texel. ([Derived points](../topics/rc_for_sampling_and_guiding_rcpg.md#derived-points), rc_for_sampling_and_guiding_rcpg)
- Remove temporal reuse from texel integration: Cone or beam tracing per texel; trade-off: no hardware support, sparse octrees might serve. ([Limits and future work](../topics/rc_for_sampling_and_guiding_rcpg.md#limits-and-future-work), rc_for_sampling_and_guiding_rcpg)
- Shade each hit in its own frame without lighting history; Get moving geometry into the same frame's tracing: Direct light by shadow ray or map; bounces need a second solve. ([Single-frame assessment](../topics/scene_representation_and_tracing.md#single-frame-assessment), scene_representation_and_tracing)
- Solve GI in the same frame before the opaque pass: PRE_OPAQUE callback; trade-off: this frame's lit color is not yet available. ([Frame order and compositor hooks](../topics/godot_integration.md#frame-order-and-compositor-hooks), godot_integration)
- Solve GI fully within one frame; Keep GI stable without temporal accumulation: World-space or screen-space solve at either hook; trade-off: same-frame hit light needs direct-light evaluation. ([Single-frame assessment](../topics/godot_integration.md#single-frame-assessment), godot_integration)
- Put moving meshes into GI within the same frame: Analytic primitives move per frame; meshes need a CPU BVH, 1.2 s at 72,012 triangles. ([Single-frame assessment](../topics/godot_projects.md#single-frame-assessment), godot_projects)
- Compute probe GI in one frame without history: VCT and LPVs compute a same-frame result by prefiltering, trading blur and leaks. ([Single-frame assessment](../topics/related_probe_gi.md#single-frame-assessment), related_probe_gi)
- Compute indirect light in one frame without history: Single-frame caches fill then render, or splat; history caches flicker and lag. ([Single-frame assessment](../topics/related_radiance_caches.md#single-frame-assessment), related_radiance_caches)
- Run GI on one frame without temporal history: BRDF-only importance sampling; trade-off: no product sampling from last frame's light. ([Single-frame assessment](../topics/related_engine_gi.md#single-frame-assessment), related_engine_gi)
- Make bitmask GI acceptable in one frame without temporal jitter: More slices per pixel, which multiplies sampling time by the slices added; screen-space RC shares one cascade's slices among the pixels a probe covers. ([Single-frame assessment](../topics/related_screen_space_gi.md#single-frame-assessment), related_screen_space_gi)
- Get screen-space GI in about 3 ms without reprojection: Fixed sample count with per-pixel seeds, box filter and mips; denoiser blurred detail. ([Path of Exile 1's screen-space GI](../topics/related_screen_space_gi.md#path-of-exile-1s-screen-space-gi), related_screen_space_gi)
- Keep AO and first-bounce noise low in a single frame: LSAO is deterministic and noise-free; trade-off is banding and blur from shared directions. ([Single-frame assessment](../topics/related_screen_space_gi.md#single-frame-assessment), related_screen_space_gi)
- Get several bounces in one frame without temporal lag: Stored hit distances give N bounces in one frame, opaque scenes only. ([Multi-bounce](../topics/light_transport_alternatives.md#multi-bounce), light_transport_alternatives)
- Keep GI stable without temporal accumulation: Screen-space cascades recomputed each frame; trade-off: no temporal smoothing, so every frame pays full cost. ([ExileCon 2023 and Path of Exile 2](../topics/history_and_landscape.md#exilecon-2023-and-path-of-exile-2), history_and_landscape)
- Keep GI stable without temporal accumulation; Run 3D world-space RC in real time within one frame: Single-frame computation from current rays; trade-off: full cost is paid every frame. ([Single-frame assessment](../topics/history_and_landscape.md#single-frame-assessment), history_and_landscape)

## Keep GI stable under motion

- Keep GI stable without temporal accumulation: Full solve each frame with no noise; trade-off: one extra full solve per bounce. ([Single-frame assessment](../topics/holographic_rc.md#single-frame-assessment), holographic_rc)

- Keep GI steady as the camera moves: World-stable probes need no screen-space upscaling; trade-off is world-space memory. ([Why world space](../topics/3d_world_space.md#why-world-space), 3d_world_space)
- Keep GI pinned to walls as the camera moves: World-fixed face probes hold position; trade-off: design document and code disagree on most values. ([genos-engine](../topics/3d_world_space_implementations.md#genos-engine), 3d_world_space_implementations)
- Smooth probe radiance over frames without resetting on camera motion: Decayed-sum history averages frames; trade-off: lag, and camera motion never resets. ([Merge and temporal reuse](../topics/3d_world_space_implementations.md#merge-and-temporal-reuse), 3d_world_space_implementations)
- Keep GI stable while lights move: Running average for static scenes, 0.92 blend for moving lights; trade-off: stale history at speed. ([Merge, history and shading](../topics/3d_world_space_implementations.md#merge-history-and-shading), 3d_world_space_implementations)

- Stop GI flicker when the camera moves: Min/max probes fix depth jumps; frame-indexed jitter and accumulation fix the rest but need history. ([Temporal stability](../topics/3d_screen_space.md#temporal-stability), 3d_screen_space)
- Keep min/max probes stable under camera motion: Continuous min/max blurs foreground and background classes separately and stays stable at any downscale factor. ([Min/max probes](../topics/3d_screen_space.md#minmax-probes), 3d_screen_space)

- Keep indirect light stable under camera motion in URP: Realtime lightmaps are most stable; trade-off is no dynamic emissive light. ([Gerassimov (2026): RC against Unity's GI](../topics/3d_screen_space_theses.md#gerassimov-2026-rc-against-unitys-gi), 3d_screen_space_theses)

## Reduce noise and fireflies

Start with [What a single frame allows](../topics/single_frame_3d_rc.md#what-a-single-frame-allows), then [Ray splitting](../topics/3d_world_space.md#ray-splitting) for samples per direction. Filters and denoisers are in the glossary under [Denoising, upscaling and temporal reuse](../topics/supporting_techniques.md#denoising-upscaling-and-temporal-reuse).

- Keep per-frame noise low without temporal averaging: Enough rays per stored direction; trade-off is more rays and more time. ([What a single frame allows](../topics/single_frame_3d_rc.md#what-a-single-frame-allows), single_frame_3d_rc)
- Keep spectral colour noise low with few wavelengths: Hero wavelength sampling weighted by balance heuristic; trade-off: needs accumulation to lose colour noise. ([Spectral transport](../topics/volumetric_and_radiative_transfer.md#spectral-transport), volumetric_and_radiative_transfer)
- Keep fireflies out of sparse distance-sampled media estimates: Minimum-extinction control variate; trade-off: 86% of samples contributed nothing in one test. ([Transmittance estimation (Peters 2025)](../topics/volumetric_and_radiative_transfer.md#transmittance-estimation-peters-2025), volumetric_and_radiative_transfer)
- Cut single-frame noise at contact range: Larger probe footprints give more samples per cone; trade-off is spatial detail. ([Samples per direction per frame (derived)](../topics/3d_world_space.md#samples-per-direction-per-frame-derived), 3d_world_space)
- Smooth probe radiance over frames without resetting on camera motion: Decayed-sum history averages frames; trade-off: lag, and camera motion never resets. ([Merge and temporal reuse](../topics/3d_world_space_implementations.md#merge-and-temporal-reuse), 3d_world_space_implementations)
- Remove fireflies from small nearby lights: nearEmissiveIrradiance cuts and re-adds near emitters; trade-off: a second analytic lighting term. ([split-radiance-cascades-webgpu: browser build](../topics/3d_world_space_implementations.md#split-radiance-cascades-webgpu-browser-build), 3d_world_space_implementations)
- Cut single-frame noise at equal rays: The descent sampler over a merged cascade can importance-sample a near-field pass or specular rays from the same frame's cascades. ([Single-frame assessment](../topics/rc_for_sampling_and_guiding.md#single-frame-assessment), rc_for_sampling_and_guiding)
- Stop per-level weight products from growing across cascade levels: Collapsing each level's weight keeps variance bounded; no contribution weight crosses levels. ([Method](../topics/rc_for_sampling_and_guiding_reservoir_cascades.md#method), rc_for_sampling_and_guiding_reservoir_cascades)
- Keep reuse variance from compounding across cascade depth: Theorem bounds each level's transfer factor, so injections multiply by a depth-independent constant. ([Theory](../topics/rc_for_sampling_and_guiding_reservoir_cascades.md#theory), rc_for_sampling_and_guiding_reservoir_cascades)
- Smooth noisy probe-based reflections: Bilateral reflection filter; trade-off: blurs detail and is skipped at roughness 0.3 and up. ([HDDAGI](../topics/godot_integration.md#hddagi), godot_integration)
- Denoise probe GI without NRD: SVGF plus à-trous filtering; trade-off: temporal lag when light changes. ([Screen probes in #122999](../topics/godot_integration.md#screen-probes-in-122999), godot_integration)
- Cut noise in path-traced indirect light without many samples per pixel: DDGI as a light inside ReSTIR, reusing samples; trades leaks and grid resolution. ([DDGI resampling](../topics/related_probe_gi.md#ddgi-resampling), related_probe_gi)
- Denoise few-sample ray-traced shadows and AO: Halton-rotated cone shadows with a single-scalar SVGF variant and Karis clamp. ([PICA PICA (Ray Tracing Gems chapter 25)](../topics/related_radiance_caches.md#pica-pica-ray-tracing-gems-chapter-25), related_radiance_caches)
- Keep AO and first-bounce noise low in a single frame: LSAO is deterministic and noise-free; trade-off is banding and blur from shared directions. ([Single-frame assessment](../topics/related_screen_space_gi.md#single-frame-assessment), related_screen_space_gi)
- Keep 3D GI noise-free in world-space voxels: Re-voxelized world-space cascades recomputed each frame; trade-off: contact shadows cost more. ([From 2D tests to the paper (2022 to 2023)](../topics/history_and_landscape.md#from-2d-tests-to-the-paper-2022-to-2023), history_and_landscape)
- Smooth noise without blurring depth or colour edges: Bilateral filter; trade-off: range weights need a full-resolution guide such as depth. ([Bilateral filter](../topics/supporting_techniques.md#bilateral-filter), supporting_techniques)
- Reconstruct path-traced images from per-pixel features: BMFR; trade-off: needs albedo, normal and position feature buffers. ([BMFR](../topics/supporting_techniques.md#bmfr), supporting_techniques)
- Denoise ray-traced lighting with a vendor neural model: DLSS Ray Reconstruction; trade-off: no algorithm published. ([DLSS Ray Reconstruction](../topics/supporting_techniques.md#dlss-ray-reconstruction), supporting_techniques)
- Denoise a wide area in few passes with edge stops: Edge-avoiding à-trous filter; trade-off: only approximates a large bilateral filter. ([Edge-avoiding à-trous wavelet filter](../topics/supporting_techniques.md#edge-avoiding-à-trous-wavelet-filter), supporting_techniques)
- Denoise offline references with a pretrained network: OIDN; trade-off: used here offline for references only. ([OIDN](../topics/supporting_techniques.md#oidn), supporting_techniques)
- Filter textures per sample without blending before shading: Stochastic texture filtering; trade-off: noise needs accumulation or a denoiser. ([Stochastic texture filtering and stochastic interpolation](../topics/supporting_techniques.md#stochastic-texture-filtering-and-stochastic-interpolation), supporting_techniques)
- Denoise one-sample path tracing using temporal history: SVGF; trade-off: needs motion vectors and history. ([SVGF](../topics/supporting_techniques.md#svgf), supporting_techniques)
- Model frame-to-frame correlation of reused estimates: Autocorrelation decays as φ^k; trade-off: assumes stationary, geometrically decaying correlation. ([AR(1)](../topics/supporting_techniques_transport_and_math.md#ar1), supporting_techniques_transport_and_math)
- Fit a robust estimate that resists outliers: Reweights least squares from last residuals; trade-off: iteration count and regularization near zero. ([IRLS](../topics/supporting_techniques_transport_and_math.md#irls), supporting_techniques_transport_and_math)

## Recover contact detail, sharp shadows and small lights
