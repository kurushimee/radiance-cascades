## Debug, validate and compare

Start with [Recurring implementation bugs](../topics/artifacts_and_fixes.md#recurring-implementation-bugs) and [Debugging routine](../topics/artifacts_and_fixes.md#debugging-routine). Metrics and reference checks are in the glossary under [Image metrics](../topics/supporting_techniques_transport_and_math.md#image-metrics) and [White furnace test](../topics/supporting_techniques_transport_and_math.md#white-furnace-test).

- Rank RC families by quality per millisecond: Path-traced reference renders of one scene; trade-off is a reference build per scene. ([Open problems, ranked](../topics/single_frame_3d_rc.md#open-problems-ranked), single_frame_3d_rc)
- Compare single-frame RC with amortized GI at equal noise: Equal-noise ray counting; trade-off is amortized systems hide ray debt across frames. ([Connections](../topics/performance.md#connections), performance)
- Measure world-space 3D RC inside Godot's RenderingDevice: gomezzz's software BVH tracer; trade-off is a CPU BVH build of about 1.22 s. ([Godot](../topics/performance.md#godot), performance)
- Measure a RenderingDevice compute tracer on RC rays; Find how the ray rate falls with cascade level; Test whether hardware-RT results hold with a compute tracer; Rerun unnormalisable timings under known settings: Compute BVH or voxel DDA timed per pass; trade-off is only a frame-capped floor exists. ([Open questions](../topics/performance.md#open-questions), performance)
- Find which RC pass dominates a 2D frame: Per-pass timestamp queries; trade-off is one GPU and mostly one scene. ([Per-pass cost in one 2D solver](../topics/performance.md#per-pass-cost-in-one-2d-solver), performance)
- Compare RC designs across resolutions fairly: Milliseconds per megapixel normalises pixel count; trade-off is it ignores rays per pixel. ([Time per megapixel (derived)](../topics/performance.md#time-per-megapixel-derived), performance)
- Check 2D RC lighting against a reference: White furnace test; 2D radiometry factors differ from 3D references. ([Radiometry in flatland](../topics/core_theory.md#radiometry-in-flatland), core_theory)
- Find whether direction-first 3D merging beats a shader trilinear blend; Find the best nested equal-area map at low direction counts; Measure whether pre-averaging costs quality in 3D: Direction-first 3D layout with hardware trilinear fetch; trade-off is a clamp margin per region. ([Open questions](../topics/cascade_layout_and_merging.md#open-questions), cascade_layout_and_merging)
- Find which merge stage breaks energy: One level at a time and trivial scenes isolate the broken stage. ([Debugging routine](../topics/artifacts_and_fixes.md#debugging-routine), artifacts_and_fixes)
- Tell implementation bugs apart from ringing and leaks: Bug classes table catalogues energy-breaking code errors; needs reading the code. ([Recurring implementation bugs](../topics/artifacts_and_fixes.md#recurring-implementation-bugs), artifacts_and_fixes)
- Find which interval or offset causes a wrong pixel: Visualize contributing intervals, compare traced and extended rays; trade-off: manual inspection. ([Debugging](../topics/holographic_rc.md#debugging), holographic_rc)
- Check a holographic pipeline against a reference: Reference HRC following the paper; trade-off: no published timings. ([amitabha](../topics/holographic_rc_implementations.md#amitabha), holographic_rc_implementations)
- Compare extension start against tracing three levels; Compare HRC codes on one GPU at one size; Check the opacity gate against thin occluders: Extend from cascade 0 or trace lowest three levels; trade-off: accuracy gap unmeasured. ([Open questions](../topics/holographic_rc_implementations.md#open-questions), holographic_rc_implementations)
- Check RC merge accuracy against a path tracer: CoreCascade's harness compares RC variants and a path tracer on one image. ([CPU references and research harnesses](../topics/2d_implementations.md#cpu-references-and-research-harnesses), 2d_implementations)
- Tell what a demo's code actually computes: Read the code, not the prose: articles and code disagree in several listed places. ([Connections](../topics/2d_articles_and_demos.md#connections), 2d_articles_and_demos)
- Compare teaching demo layouts at equal resolution: No demo reports timings, so a measured comparison at equal resolution is needed. ([Open questions](../topics/2d_articles_and_demos.md#open-questions), 2d_articles_and_demos)
- Identify which fix a shader actually implements; Compare fixes across forks at equal brightness: Identify a fix by its code, not its switch number or title; forks reuse numbers. ([Connections](../topics/2d_shadertoys.md#connections), 2d_shadertoys)
- Compare extended gathering cost with merged cascades: Extended gathering vs merged stacks at equal penumbra quality; no measured cost yet. ([Open questions](../topics/2d_shadertoys.md#open-questions), 2d_shadertoys)
- Compare ringing fixes inside one testbed framework: MERGE_FIX modes selecting bilinear, midpoint, Dolkar or parallax merges; bilinear costs 16 traces per texel. ([The testbed line](../topics/2d_shadertoys.md#the-testbed-line), 2d_shadertoys)
- Reproduce Split RC's paper settings in one codebase: Matches paper settings with hardware RT; builds only next to a sefirot checkout. ([chandra](../topics/3d_world_space_implementations.md#chandra), 3d_world_space_implementations)
- Measure RC against DDGI on station scenes before adopting it: Station gates; RC update costs 1.15 to 1.57 times DDGI; fails leak and far-field gates. ([Measurements against DDGI](../topics/3d_world_space_implementations.md#measurements-against-ddgi), 3d_world_space_implementations)
- Catch light leaks through walls before shipping a probe layout: Leak gates on paired rooms and offset sweeps; trade-off: thresholds tied to erhe's own scenes. ([Stations and gates](../topics/3d_world_space_implementations.md#stations-and-gates), 3d_world_space_implementations)
- Compare radiance cascades with ReSTIR: Two RC variants in one engine; trade-off is no merge structure and no measurements. ([BeansEngine](../topics/3d_screen_space_implementations.md#beansengine), 3d_screen_space_implementations)
- Measure the error of perspective-correct min/max interpolation on real G-buffers: NfBSz1 against bilinear 3D and selective subsets; no error metric exists yet. ([Open questions](../topics/3d_screen_space_implementations.md#open-questions), 3d_screen_space_implementations)
- Find surfel RC bugs by reading code, not running it: Stack corruption, barrier misuse, zero merges and shared seeds; found by reading, untested. ([Found by reading the code (not run)](../topics/3d_surface_probes.md#found-by-reading-the-code-not-run), 3d_surface_probes)
- Check the GI result against a reference image: Per-pixel uniform random direction, accumulated; slow to converge and no sky term. ([Ground-truth pass](../topics/3d_surface_probes.md#ground-truth-pass), 3d_surface_probes)
- Find which pass writes a given surfel buffer: Per-pass reads and writes; debug passes share the table, so filter them out. ([Pass table](../topics/3d_surface_probes.md#pass-table), 3d_surface_probes)
- Find which surfel pass dominates frame time on a GPU: Per-pass timings; hash insertion costs most on the 890M, recycling on the 4070. ([Performance](../topics/3d_surface_probes.md#performance), 3d_surface_probes)
- Check whether surfel error stays balanced across depth: Interval length fixed while surfels grow with depth; error balances at one depth. ([Read against the theory (derived)](../topics/3d_surface_probes.md#read-against-the-theory-derived), 3d_surface_probes)
- Compare path guiders at equal frame time: Equal-time runs at 33.33 ms; trade-off: each method gets the sample count its speed allows. ([Evaluation](../topics/rc_for_sampling_and_guiding_rcpg.md#evaluation), rc_for_sampling_and_guiding_rcpg)
- Know what gomezzz's tests check: Tests cover GPU traversal and BVH export; they render nothing and measure no lighting error. ([Files](../topics/godot_projects.md#files), godot_projects)
- Know the GI pass cost in frame time: Frame-time records on RTX 4060 Ti; trade-off: old runs, display-capped, not isolated. ([Measurements](../topics/godot_projects.md#measurements), godot_projects)
- Measure gomezzz's per-level error against a reference: Independent brute-force reference per level; trade-off: none is built, so error is unmeasured. ([Open questions](../topics/godot_projects.md#open-questions), godot_projects)
- Choose a real-time GI class by the effects it can reach: Survey table: RSM and voxels cover most effects; DOM and screen space miss some. ([Lambru's comparison of engine GI classes](../topics/related_probe_gi.md#lambrus-comparison-of-engine-gi-classes), related_probe_gi)
- Get unbiased error estimates from a deterministic rule: Cranley-Patterson shift; trade-off: several independent shifts are needed to measure error. ([Cranley-Patterson rotation](../topics/supporting_techniques.md#cranley-patterson-rotation), supporting_techniques)
- Denoise offline references with a pretrained network: OIDN; trade-off: used here offline for references only. ([OIDN](../topics/supporting_techniques.md#oidn), supporting_techniques)
- Compare spread across signals of different brightness: σ over μ removes scale; trade-off: meaningless when the mean is near zero. ([Coefficient of variation](../topics/supporting_techniques_transport_and_math.md#coefficient-of-variation), supporting_techniques_transport_and_math)
- Rank render errors the way viewers perceive them: Perception-based difference map; trade-off: depends on viewing distance and pixel size. ([FLIP](../topics/supporting_techniques_transport_and_math.md#flip), supporting_techniques_transport_and_math)
- Check RC against 2D wave-optics reference fields: Hankel Green's function gives the outgoing reference; trade-off: a 2D Helmholtz reference only. ([Hankel functions](../topics/supporting_techniques_transport_and_math.md#hankel-functions), supporting_techniques_transport_and_math)
- Check whether ray hits cluster rather than scatter at random: Variance-to-mean ratio; trade-off: needs enough samples for a stable variance. ([Index of dispersion](../topics/supporting_techniques_transport_and_math.md#index-of-dispersion), supporting_techniques_transport_and_math)
- Measure render error numerically against a reference: MSE and PSNR summarize error; trade-off: HDR needs a stated maximum, MAPE a floor. ([MSE, RMSE, MAE, PSNR, MAPE](../topics/supporting_techniques_transport_and_math.md#mse-rmse-mae-psnr-mape), supporting_techniques_transport_and_math)
- Score how structurally similar two renders are: Local means, variances and covariance; trade-off: sensitive to window size and constants. ([SSIM](../topics/supporting_techniques_transport_and_math.md#ssim), supporting_techniques_transport_and_math)
- Check that a renderer conserves energy end to end: Uniform unit environment must reproduce itself; trade-off: tests only uniform lighting. ([White furnace test](../topics/supporting_techniques_transport_and_math.md#white-furnace-test), supporting_techniques_transport_and_math)

## Get GI into Godot and other engines' shading

Start with [Getting GI into shading](../topics/godot_integration.md#getting-gi-into-shading) and [Frame order and compositor hooks](../topics/godot_integration.md#frame-order-and-compositor-hooks), then the [Godot projects](../topics/godot_projects.md).

- Get GI into Godot's opaque shading: Per-material IRRADIANCE composite; trade-off is ShaderMaterial on every opaque material and SSAO off. ([Lighting the hits and the composite](../topics/single_frame_3d_rc.md#lighting-the-hits-and-the-composite), single_frame_3d_rc)
- Choose a 3D RC family for a Godot implementation: Hybrid of screen near field and sparse world probes; trade-off is unmeasured quality. ([The families compared](../topics/single_frame_3d_rc.md#the-families-compared), single_frame_3d_rc)
- Trace rays in a Godot compute shader without hardware RT: Compute tracer with segment-length structures; trade-off is unknown throughput, floor 0.375 G segments/s. ([Tracing and scene representation under `RenderingDevice`](../topics/single_frame_3d_rc.md#tracing-and-scene-representation-under-renderingdevice), single_frame_3d_rc)
- Add holographic GI to a TypeGPU app: Call create with size, medium and optional source; trade-off: memory grows as N² log N. ([Options and outputs](../topics/holographic_rc_implementations.md#options-and-outputs), holographic_rc_implementations)
- Light a Godot 2D scene with radiance cascades; Run GI in Godot with plain nodes and no scripts: Pre-averaged layout with imageLoad merge: fast, but nearest-neighbour, not filtered. ([Godot](../topics/2d_implementations.md#godot), 2d_implementations)
- Add radiance cascades to a WebGPU app without hand-written WGSL: TGSL package; built-in tracer treats surfaces as opaque. ([TypeGPU (Software Mansion)](../topics/2d_implementations.md#typegpu-software-mansion), 2d_implementations)
- Light a 2D Unity scene with a URP-friendly RC: Direction-first blocks and one bilinear fetch; render scale dominates speed. ([Unity and other ports](../topics/2d_implementations.md#unity-and-other-ports), 2d_implementations)
- Feed RC into an existing DDGI probe path: Reduces cascade 0 into DDGI-format maps; trade-off: reduce is about 60% of an update. ([Reduce into the probe field](../topics/3d_world_space_implementations.md#reduce-into-the-probe-field), 3d_world_space_implementations)
- Add radiance cascades to an engine without writing a renderer: Unreal and Unity plugins; both are incomplete or unstable and have no timings. ([Engine plugins](../topics/3d_screen_space_implementations.md#engine-plugins), 3d_screen_space_implementations)
- Make screen-space GI in a three.js scene: BVH in GLSL with probes on a screen grid; trade-off is static geometry, emitter-only light. ([three-rc](../topics/3d_screen_space_implementations.md#three-rc), 3d_screen_space_implementations)
- Trace RC rays in Godot with hardware ray tracing: Godot's Vulkan-only pipeline lacks ray queries in compute and mesh BLAS support in release builds. ([Hardware ray tracing](../topics/scene_representation_and_tracing.md#hardware-ray-tracing), scene_representation_and_tracing)
- Trace voxel cascades in Godot with 32-bit integer operations only: Integer walk with 8 fractional bits needs no 64-bit atomics. ([HDDAGI's voxel cascades](../topics/scene_representation_and_tracing_voxels_and_bvhs.md#hddagis-voxel-cascades), scene_representation_and_tracing_voxels_and_bvhs)
- Voxelize Godot meshes without geometry shaders or mesh RIDs: Per-axis raster passes or triangle compute; skinned meshes need their own path. ([Voxelization in Godot](../topics/scene_representation_and_tracing_voxels_and_bvhs.md#voxelization-in-godot), scene_representation_and_tracing_voxels_and_bvhs)
- Read world positions from the depth buffer: Inverse projection of depth; trade-off: TAA jitter shifts reconstructed points every frame. ([Buffers in a callback](../topics/godot_integration.md#buffers-in-a-callback), godot_integration)
- Solve GI in the same frame before the opaque pass: PRE_OPAQUE callback; trade-off: this frame's lit color is not yet available. ([Frame order and compositor hooks](../topics/godot_integration.md#frame-order-and-compositor-hooks), godot_integration)
- Get GI into Godot's opaque shading per pixel; Add GI after shading without changing materials: Per-material IRRADIANCE hook; trade-off: every opaque material must be a ShaderMaterial. ([Getting GI into shading](../topics/godot_integration.md#getting-gi-into-shading), godot_integration)
- Get dynamic GI without per-scene authoring: SDFGI cascades; trade-off: static occluders only, and stale distance fields after moves. ([SDFGI, the shipped GI](../topics/godot_integration.md#sdfgi-the-shipped-gi), godot_integration)
- Show 2D GI in a Godot scene without CPU readback: Main-device Texture2DRD output read by material shaders; trade-off: needs main-device setup. ([2D projects](../topics/godot_projects.md#2d-projects), godot_projects)
- Add screen-space AO or GI as a compositor effect: Compositor passes read depth and normals; trade-off: they edit lit colour, so albedo is missing. ([Compositor effect projects](../topics/godot_projects.md#compositor-effect-projects), godot_projects)
- Get GI into Godot's opaque shading: Material override swap writes RC into shading; trade-off: materials are replaced and rebuilt. ([Godot integration](../topics/godot_projects.md#godot-integration), godot_projects)
- Get world-space 3D GI from a compute pass in Godot: Five-level compute merge over a CPU BVH and analytic primitives; trade-off: static triangles need rebuilds. ([gomezzz: world-space 3D RC](../topics/godot_projects.md#gomezzz-world-space-3d-rc), godot_projects)
- Light a world with voxel-cone RC inside Forward+: Compositor effect over voxel clipmaps; trade-off: albedo is guessed from lit colour. ([Phreakyx: voxel-cone RC as a GDExtension](../topics/godot_projects.md#phreakyx-voxel-cone-rc-as-a-gdextension), godot_projects)
- Add screen-space GI to a shipped game without reprojection: Per-pixel point-light GI in 3 ms; trade-off: the denoiser blurs fine detail. ([Path of Exile 1: shadows and GI](../topics/history_and_landscape.md#path-of-exile-1-shadows-and-gi), history_and_landscape)

## Light the hits

Start with [Lighting the hits and the composite](../topics/single_frame_3d_rc.md#lighting-the-hits-and-the-composite) and [Shading the hit](../topics/scene_representation_and_tracing.md#shading-the-hit).

- Get same-frame radiance at RC hits: Shadow rays or per-frame light injection; trade-off is the shadow cost at each hit. ([Lighting the hits and the composite](../topics/single_frame_3d_rc.md#lighting-the-hits-and-the-composite), single_frame_3d_rc)
- Shade distance-field hits that have no UVs or material: Cards store material and lighting per mesh but miss some surfaces. ([Lumen's surface cache](../topics/scene_representation_and_tracing.md#lumens-surface-cache), scene_representation_and_tracing)
- Light off-screen distance-field hits without shading them: Copy the lit screen into voxels so hits read light; adds lag. ([Radiance at the hit from the lit frame](../topics/scene_representation_and_tracing.md#radiance-at-the-hit-from-the-lit-frame), scene_representation_and_tracing)
- Shade each hit in its own frame without lighting history: Direct light by shadow ray or map; bounces need a second solve. ([Single-frame assessment](../topics/scene_representation_and_tracing.md#single-frame-assessment), scene_representation_and_tracing)
- Light off-screen hits in the same frame: Direct-light evaluation at each hit; trade-off: extra direct-light cost per hit. ([Open questions](../topics/godot_integration.md#open-questions), godot_integration)
- Get colour at SDF hits without stored materials: Radiance cache atlas reprojected each frame; trade-off: off-screen surfaces stay unlit until seen. ([Brixelizer GI](../topics/related_engine_gi.md#brixelizer-gi), related_engine_gi)
- Cache lighting on mesh surfaces for cheap ray hits: Offline capture cards store lit surface properties; trade-off: capture cost and memory per mesh. ([Surface cache cards](../topics/supporting_techniques_structures_and_tracing.md#surface-cache-cards), supporting_techniques_structures_and_tracing)

## Handle moving and dynamic geometry

Start with [Tracing and scene representation under RenderingDevice](../topics/single_frame_3d_rc.md#tracing-and-scene-representation-under-renderingdevice) and [World-space inputs](../topics/godot_integration.md#world-space-inputs). Rebuilding structures every frame is in [Triangle BVHs](../topics/scene_representation_and_tracing_voxels_and_bvhs.md#triangle-bvhs) and [Voxels](../topics/scene_representation_and_tracing_voxels_and_bvhs.md#voxels).

- Keep rebuild cost proportional to moving content: Static structure plus capped per-frame dynamic one; trade-off is maintaining two structures. ([Open problems, ranked](../topics/single_frame_3d_rc.md#open-problems-ranked), single_frame_3d_rc)
- Relight a dynamic 2D scene with soft shadows each frame: Bilinear cascade merge with per-cascade screen textures; no timings or resolution reported. ([Kelkar et al. (IEEE ICWITE 2025)](../topics/2d_articles_and_demos.md#kelkar-et-al-ieee-icwite-2025), 2d_articles_and_demos)
- Keep surfels attached to geometry that moves: GIBS transform IDs, described but not implemented; surfels stay in world space. ([Limitations and future work](../topics/3d_surface_probes.md#limitations-and-future-work), 3d_surface_probes)
- Keep GI dynamic with no baking for moving furniture: Dynamic surfel RC with clipmap probes; each bounce converges over about 28 frames. ([Love and Deepspace](../topics/3d_surface_probes.md#love-and-deepspace), 3d_surface_probes)
- Keep moving objects in a distance field without re-rasterizing them: Depth-buffer marking updates the field from the screen; removal is random and approximate. ([daGI2: narrow-band clips without bricks](../topics/scene_representation_and_tracing.md#dagi2-narrow-band-clips-without-bricks), scene_representation_and_tracing)
- Get moving geometry into the same frame's tracing: Per-frame dynamic structure such as a GPU BVH rebuild; costs rebuild time every frame. ([Single-frame assessment](../topics/scene_representation_and_tracing.md#single-frame-assessment), scene_representation_and_tracing)
- Keep a camera-centred distance field cheap to update: Camera-following clipmaps snap and rebuild few cascades per frame; new geometry lags. ([Sphere tracing and cheaper fields](../topics/scene_representation_and_tracing.md#sphere-tracing-and-cheaper-fields), scene_representation_and_tracing)
- Update voxel GI as the camera moves without full rebuilds: Revoxelize only newly uncovered slabs; a large move still rebuilds. ([HDDAGI's voxel cascades](../topics/scene_representation_and_tracing_voxels_and_bvhs.md#hddagis-voxel-cascades), scene_representation_and_tracing_voxels_and_bvhs)
- Rebuild a CPU BVH quickly enough when meshes move: gomezzz build takes about 1.2 s for 72,012 triangles, and moving meshes reset history. ([Other software BVHs in RC projects](../topics/scene_representation_and_tracing_voxels_and_bvhs.md#other-software-bvhs-in-rc-projects), scene_representation_and_tracing_voxels_and_bvhs)
- Keep dynamic objects in a voxel clipmap each frame: Per-frame dynamic clipmap resolves overlaps with atomicMax; geometry thinner than a voxel still leaks. ([Voxel tracing measured for RC](../topics/scene_representation_and_tracing_voxels_and_bvhs.md#voxel-tracing-measured-for-rc), scene_representation_and_tracing_voxels_and_bvhs)
- Scroll cascades with the camera without full rebuilds: Cascade scrolling with dirty slabs; trade-off: a shift of 128 cells rebuilds the whole cascade. ([SDFGI, the shipped GI](../topics/godot_integration.md#sdfgi-the-shipped-gi), godot_integration)
- Light dynamic objects in a voxel GI: Per-object distance fields with card lighting; trade-off: cells times objects cost unless binned. ([The SDFGI plan](../topics/godot_integration.md#the-sdfgi-plan), godot_integration)
- Replace a BVH rebuild with a per-frame proxy scene: Grow analytic primitives into per-frame proxies; trade-off: proxies cover only 64 objects. ([Open questions](../topics/godot_projects.md#open-questions), godot_projects)
- Put moving meshes into GI within the same frame: Analytic primitives move per frame; meshes need a CPU BVH, 1.2 s at 72,012 triangles. ([Single-frame assessment](../topics/godot_projects.md#single-frame-assessment), godot_projects)
- Update a voxel scene when objects move: Dynamic objects rasterized into a separate buffer each frame; light reinjected only when lights move. ([Voxel cone tracing](../topics/related_probe_gi.md#voxel-cone-tracing), related_probe_gi)
- Light dynamic scenes on phones: Deferred screen probes over DDGI-style probes; trade-off: an extra G-buffer target. ([Mobile path](../topics/related_engine_gi.md#mobile-path), related_engine_gi)
- Keep world probe GI cheap as the scene scrolls: Feedback-steered updates and scroll-in hand-off; trade-off: probes refresh about every 48 frames. ([Radiance grid](../topics/related_engine_gi.md#radiance-grid), related_engine_gi)
- Keep camera-following probes and voxels cheap as the view moves: Clipmap windows rewrite only newly exposed strips; trade-off: fixed resolution per nested level. ([Clipmaps and toroidal addressing](../topics/supporting_techniques_structures_and_tracing.md#clipmaps-and-toroidal-addressing), supporting_techniques_structures_and_tracing)

## Run the passes: dispatch, order and merge

Start with [Tracing and merging order](../topics/cascade_layout_and_merging.md#tracing-and-merging-order) and [Running the compute work](../topics/godot_integration.md#running-the-compute-work). Barriers and subgroups are in the glossary under [Frameworks and GPU APIs](../topics/supporting_techniques_transport_and_math.md#frameworks-and-gpu-apis).

- Keep parent lookups fixed across cascades without reprojection: Bin-shift scaling; trade-off is that it holds only at ×4 directions and ×4 intervals. ([Leaks without history](../topics/single_frame_3d_rc.md#leaks-without-history), single_frame_3d_rc)
- Keep a parent's cone when merging directions: Cone merge averages all child directions; each merge reads more children. ([Angle: cones, not rays](../topics/core_theory.md#angle-cones-not-rays), core_theory)
- Hold only two cascades in memory at once: Ping-pong textures reused for each cascade; trade-off is each cascade depends on the one above. ([Containers](../topics/cascade_layout_and_merging.md#containers), cascade_layout_and_merging)
- Find whether direction-first 3D merging beats a shader trilinear blend: Direction-first 3D layout with hardware trilinear fetch; trade-off is a clamp margin per region. ([Open questions](../topics/cascade_layout_and_merging.md#open-questions), cascade_layout_and_merging)
- Keep only two cascades live during the merge: Fused top-down schedule; trade-off is tracing cannot overlap merging. ([Tracing and merging order](../topics/cascade_layout_and_merging.md#tracing-and-merging-order), cascade_layout_and_merging)
- Budget dispatch overhead for many small compute passes: Plan dispatch overhead around 76 to 82 passes per frame; trade-off: per-pass barrier cost. ([Single-frame assessment](../topics/holographic_rc_implementations.md#single-frame-assessment), holographic_rc_implementations)
- Refresh levels within a Shadertoy pass limit: Three-frame ring computes levels over frames; trade-off: image lags about two frames. ([tfKyRw (youssef_afella)](../topics/holographic_rc_implementations.md#tfkyrw-youssef_afella), holographic_rc_implementations)
- Gather light from wide directions without merging cascades: Extended gathering; trade-off: fixed 120 px offset suits only about 667 px width. ([Extended gathering](../topics/2d_shadertoys.md#extended-gathering), 2d_shadertoys)
- Merge cascades without a top-down pass: Per-pixel front-to-back composite; trade-off: 960 fetches per pixel and light a frame late. ([Independent codes](../topics/2d_shadertoys.md#independent-codes), 2d_shadertoys)
- Cut merge work without growing cascade textures: Pre-averaging; trade-off is a SIMD quad layout with negligible gain on SIMD. ([Gavras (2025): SPWI on Metal](../topics/3d_screen_space_theses.md#gavras-2025-spwi-on-metal), 3d_screen_space_theses)
- Order surfel passes so each reads finished data: Spawn reads last frame's hash grid; merge runs coarse to fine; recycling runs last. ([Frame order](../topics/3d_surface_probes.md#frame-order), 3d_surface_probes)
- Pass far-range light from coarse cascades down to fine ones: Nearest parent surfels weighted by distance and normal; no visibility test, so leaks. ([Merging (`merge.slang`)](../topics/3d_surface_probes.md#merging-mergeslang), 3d_surface_probes)
- Find which pass writes a given surfel buffer: Per-pass reads and writes; debug passes share the table, so filter them out. ([Pass table](../topics/3d_surface_probes.md#pass-table), 3d_surface_probes)
- Merge cascades in one frame instead of lagging a frame: Cross-fade each ray into its parent by hit distance; top-down merge removes the one-frame lag. ([X3XfRM (Mathis)](../topics/3d_surface_probes.md#x3xfrm-mathis), 3d_surface_probes)
- Run GI compute on the render thread without stalls: Main device on the render thread; trade-off: work must fit render-thread callbacks. ([Running the compute work](../topics/godot_integration.md#running-the-compute-work), godot_integration)
- Avoid dispatch, sampling and ping-pong bugs seen in these projects: Each rule names the bug it prevents and the project where it was seen. ([Checklist from these projects](../topics/godot_projects.md#checklist-from-these-projects), godot_projects)
- Keep sweep parallelism high while sweeping z in order: Flux Registers Sweep: register pressure caps blocks near 400 threads. ([Sweep solvers for radiative transfer](../topics/light_transport_alternatives.md#sweep-solvers-for-radiative-transfer), light_transport_alternatives)
- Parallelize one sweep across the GPU without wavefront dependencies: One thread per ray removes dependencies but needs atomic adds. ([Three ways to parallelize a sweep](../topics/light_transport_alternatives.md#three-ways-to-parallelize-a-sweep), light_transport_alternatives)
- Prototype GI variants without hand-written resource barriers: Render graph derives barriers from declared resources; trade-off: engine is not multithreaded or optimized. ([Sannikov's tools](../topics/history_and_landscape.md#sannikovs-tools), history_and_landscape)
- Keep RC merges associative and linear in compositing: Premultiplied over operator; trade-off: colour must be stored times alpha. ([Premultiplied alpha and "over"](../topics/supporting_techniques_structures_and_tracing.md#premultiplied-alpha-and-over), supporting_techniques_structures_and_tracing)
- Order GPU writes between dependent compute passes: UAV barriers finish earlier accesses first; trade-off: barriers stall work between passes. ([UAV barriers and typed UAV loads](../topics/supporting_techniques_transport_and_math.md#uav-barriers-and-typed-uav-loads), supporting_techniques_transport_and_math)

## Place and manage probes, surfels and charts

Start with [Probe placement](../topics/cascade_layout_and_merging.md#probe-placement), then [Probe placement](../topics/3d_screen_space.md#probe-placement) in screen space, [Sparse probes near surfaces](../topics/3d_world_space.md#sparse-probes-near-surfaces) in world space and [Surfel Radiance Cascades](../topics/3d_surface_probes.md#surfel-radiance-cascades-src-dgi) on surfaces.

- Light a generated atlas without losing contact shadows: Screen-space cascade −1 restores contact light below texel size; trade-off is texel-limited GI. ([Open problems, ranked](../topics/single_frame_3d_rc.md#open-problems-ranked), single_frame_3d_rc)
- Remove probes inside walls from world-space RC: Ray splitting spawns rays at visible surfaces; trade-off is none stated, the removal is free. ([Sparse world probes near surfaces (Split RC)](../topics/single_frame_3d_rc.md#sparse-world-probes-near-surfaces-split-rc), single_frame_3d_rc)
- Trace GI on a generated atlas without probes inside walls: Generated surface atlas; trade-off is an atlas build that handles moving meshes. ([Surface probes](../topics/single_frame_3d_rc.md#surface-probes), single_frame_3d_rc)
- Keep bilinear upper-probe weights consistent across cascades; Spread interpolation error evenly between misaligned 3D cascades; Fit probe layouts to any screen aspect ratio: Cell-centred probes with the bilinear fix; trade-off is one shared ray-offset convention. ([Probe placement](../topics/cascade_layout_and_merging.md#probe-placement), cascade_layout_and_merging)
- Make sparse RC work for volumetric fog: Probes activated along camera rays; trade-off: extra probes per frame, count unknown. ([Open questions](../topics/volumetric_and_radiative_transfer.md#open-questions), volumetric_and_radiative_transfer)
- Keep the cascade layout symmetric at any aspect ratio: Fixed cascade count and top row; width stretches, so extra probes land on the sides. ([Théo Le Goc (tlegoc), Vulkan](../topics/2d_articles_and_demos.md#théo-le-goc-tlegoc-vulkan), 2d_articles_and_demos)
- Store world-space probes only where surfaces are: Hash table of cell keys, sort and Morton codes, all using integer atomics. ([GPU building blocks](../topics/3d_world_space.md#gpu-building-blocks), 3d_world_space)
- Keep probe size constant on screen as the camera moves: Scale probes to pixel footprint and blend LODs; trade-off: seams at level boundaries. ([Placement and levels of detail](../topics/3d_world_space.md#placement-and-levels-of-detail), 3d_world_space)
- Cut the memory of 3D cascades: Store only probes near visible surfaces; trade-off: placement and hashing complexity. ([Why sparse](../topics/3d_world_space.md#why-sparse), 3d_world_space)
- Store probes only where visible surfaces need them: Hash tables with lifetimes free probes unseen for frames; trade-off: two CPU readbacks per frame. ([Frame](../topics/3d_world_space_implementations.md#frame), 3d_world_space_implementations)
- Keep GI pinned to walls as the camera moves: World-fixed face probes hold position; trade-off: design document and code disagree on most values. ([genos-engine](../topics/3d_world_space_implementations.md#genos-engine), 3d_world_space_implementations)
- Fit cascade probes to scene content within a budget: Budgeted probe grid fit; trade-off: spacing grows past the requested value when over budget. ([Layout](../topics/3d_world_space_implementations.md#layout), 3d_world_space_implementations)
- Build the probe set on the GPU without CPU readback: Retry queues and prefix passes place probes; trade-off: failed inserts retry up to 31 times. ([Passes](../topics/3d_world_space_implementations.md#passes), 3d_world_space_implementations)
- Build a dense world probe grid from an SDF scene: Sphere-trace each probe into an octahedral atlas; trade-off: full rebuilds, no per-frame update. ([Passes](../topics/3d_world_space_implementations_grids.md#passes), 3d_world_space_implementations_grids)
- Cover fine geometry that a uniform probe grid misses; Keep probe anchors stable across frames: Lumen-style subdivision or jittered candidates; trade-off is extra probes and placement logic. ([Filling gaps and keeping anchors](../topics/3d_screen_space.md#filling-gaps-and-keeping-anchors), 3d_screen_space)
- Handle non-power-of-two screens without off-screen probes: Floor probe counts; place probes at (idx + 0.5) × spacing, leaving edge pixels uncovered. ([Other findings](../topics/3d_screen_space.md#other-findings), 3d_screen_space)
- Get single-frame GI on arbitrary meshes without hand-made UVs: Generated atlas probes on arbitrary meshes; indirect contact shadows below a texel are lost. ([A generated surface atlas (Blackline Interactive)](../topics/3d_surface_probes.md#a-generated-surface-atlas-blackline-interactive), 3d_surface_probes)
- Stop NaN surfels and empty intervals from breaking surfel passes: Depth cutoff and grazing rejection; far and grazing pixels spawn no surfels. ([Artifacts and fixes](../topics/3d_surface_probes.md#artifacts-and-fixes), 3d_surface_probes)
- Place probes on mesh pieces, not in a world grid: Quad patches or voxel-block quads; lightmap-UV probes grow with the scene and distort. ([Other surface parameterizations](../topics/3d_surface_probes.md#other-surface-parameterizations), 3d_surface_probes)
- Keep probes off walls by placing them on each surface: Probes on UV charts sit on surfaces; charts need UVs and create border seams. ([Probes on surface charts](../topics/3d_surface_probes.md#probes-on-surface-charts), 3d_surface_probes)
- Free surfel slots from surfels that are no longer needed: Marker decay and neighbour counts recycle surfels; unread ones expire in about 18 passes. ([Recycling (`recycle.slang`)](../topics/3d_surface_probes.md#recycling-recycleslang), 3d_surface_probes)
- Cut the GPU cost of spawning surfels each frame: Quarter-pixel rotation tests one pixel in four; surfels arrive more slowly. ([Spawning (`spawn.slang`)](../topics/3d_surface_probes.md#spawning-spawnslang), 3d_surface_probes)
- Keep RC probes on visible surfaces, not in empty space: Surfel probes spawned from screen pixels; costs per-frame spawning, hashing and recycling state. ([Surfel Radiance Cascades (src-dgi)](../topics/3d_surface_probes.md#surfel-radiance-cascades-src-dgi), 3d_surface_probes)
- Cut the GPU time of a chart atlas: Skip padding texels: replay drops 28.6 to 5.95 ms, but replays vary 2 to 5x. ([yhyu13 surface-chart RC](../topics/3d_surface_probes.md#yhyu13-surface-chart-rc), 3d_surface_probes)
- Trace GI on phones with surfels, not software BVHs: Local-space surfels in a hash grid; gaps need transparent outer rings. ([Surfels](../topics/scene_representation_and_tracing.md#surfels), scene_representation_and_tracing)
- Move probes out of walls and deactivate dead probes: Relocation along backfaces; only static geometry moves probes, as dynamic objects destabilized them. ([DDGI](../topics/related_probe_gi.md#ddgi), related_probe_gi)
- Keep record spacing sensible near and far from the camera: Spacing in projected pixels: dense near the camera; ties the cache to the view. ([Fixes from production](../topics/related_radiance_caches.md#fixes-from-production), related_radiance_caches)
- Light a game scene with ray-traced GI without baked lightmaps: Surfels from the G-buffer: no precomputation, UVs or special meshes; needs a ray budget. ([GIBS and PICA PICA surfels](../topics/related_radiance_caches.md#gibs-and-pica-pica-surfels), related_radiance_caches)
- Avoid a burst of surfels when a wall enters view: Projected-area spawning; the counter resets only on scene reload, with no recycling. ([PICA PICA (Ray Tracing Gems chapter 25)](../topics/related_radiance_caches.md#pica-pica-ray-tracing-gems-chapter-25), related_radiance_caches)
- Share one record cache across parallel render processes: Lock, read, write and unlock on cache files; NFS locks are not always reliable. ([Radiance's practice](../topics/related_radiance_caches.md#radiances-practice), related_radiance_caches)
- Store indirect light on surface points with wavelets: Haar cube-map encoding: fixed cube-map resolution; importance ignores occlusion. ([Wavelet point-based GI](../topics/light_transport_alternatives.md#wavelet-point-based-gi), light_transport_alternatives)
- Cache lighting on mesh surfaces for cheap ray hits: Offline capture cards store lit surface properties; trade-off: capture cost and memory per mesh. ([Surface cache cards](../topics/supporting_techniques_structures_and_tracing.md#surface-cache-cards), supporting_techniques_structures_and_tracing)
