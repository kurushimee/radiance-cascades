# 2D implementations

The public 2D RC libraries, engine ports and reference codes: how each represents and traces the scene, its layout, merge and gather, its formats and parameters, its bugs, and what it measured. Tutorials and teaching demos are in [2D articles and demos](2d_articles_and_demos.md) and Shadertoy code in [2D Shadertoys](2d_shadertoys.md). Parameters and interval formulas shared across codes are compared in [cascade layout and merging](cascade_layout_and_merging.md#2d-parameters-across-implementations), merge fixes in [artifacts and fixes](artifacts_and_fixes.md), lineage and authorship in [history and landscape](history_and_landscape.md#first-public-implementations-and-the-shadertoy-lineage), timings in [performance](performance.md), and holographic codes in [holographic RC implementations](holographic_rc_implementations.md). Where a fact is owned by one of those topics, the entry here links to it.

Statements marked "derived" were computed from the sources' formulas; "inference" marks conclusions drawn here; "read from the code" marks behaviour found by reading, not by running.

## Scene representations

Flatland RC needs a scene that rays can march through quickly. The codes use six representations:

| Representation | How it is built | How rays use it | Used by |
|---|---|---|---|
| Jump-flood distance field | seed every occupied pixel with its own position, run `ceil(log2(max(W, H)))` passes with offsets halving to 1 over a 3×3 neighbourhood, store the distance to the found seed | sphere tracing | GM Shaders, jason.today, the community demo, nixonyh, IceKontroI, Youssef-Afella, Hybrid46, qJay44, tsukinousagi18, Sohojoe, kiss3d, hbattal, TypeGPU's image scenes |
| Painted or analytic signed distance | Bézier strokes written as a signed distance; analytic shapes evaluated per step | sphere tracing | fad's line (an SDF paint buffer), Peixoto, CoreCascade, SimonDev, TypeGPU's `sdf(uv)`, w3XSz4, 3cKczD, NfySzt's analytic circles |
| Bitmap with grid traversal | the scene texture itself | Amanatides–Woo DDA, first occupied texel is the hit | the futureengine2 gist, bjorn-johansson (Beer-Lambert per cell), hbattal's HRC mode |
| Occupancy grid or pyramid | a coarse "any pixel occupied" mask, or a max pyramid | skip empty cells, step finely in occupied ones | Gigi (8×8 cells over 24×24 blocks, skipping 7 px), YMM4-Radiance (9-level pyramid, empty-space skipping from the 8 px level), amida (8×8 blocks with a 64-bit mask of pixels that differ from a neighbour) |
| Mip pyramid of the scene | box or binomial downsampling of emission and opacity | cascade `c` marches mip `c` with steps growing with the mip | tmpvar's playground (2×2 box, mip `N` on cascade `N`), knowdawg (10 levels, 4×4 binomial), the shipped Switch game (progressively downsampled scene, one fetch per direction) |
| Fixed-step volume | the scene texture with emission and opacity | fixed steps accumulating `L += T·rgb·a`, `T *= 1 − a` or `T *= exp(−σ·s)` | LegitCascades (steps of `2·spacing_scaling^k` px, doubling per cascade, sampling at each step's start), kornelski's Bevy port, ZY4N, Qonfused, Sky-Meteor, CoreCascade's media, wfyyDz and its forks, tmpvar's playground |

The jump flood itself is in [scene representation and tracing](scene_representation_and_tracing.md) and in the [glossary](supporting_techniques.md#distance-fields-and-voxelization); the 2D variants differ in details that cause bugs:

- **Pass count.** `ceil(log2(max(W, H)))` is standard (jason.today, GM Shaders, qJay44). The community demo runs one more pass, 10 at 512² ([demo](../sources/2026_rc_community_site_and_wiki.md#distance-field-seed-jfa-df)). Youssef-Afella's HRC port uses a natural logarithm, 8 passes at 1920 px ending at a step of about 7.5 px instead of 1 ([Unity 2D](../sources/2024_unity_2d_rc_repositories.md#youssef-afella-hrc-port)); Hybrid46's 11 steps start at half the screen height, so the reach falls short of a 1200 px width ([assorted 2D](../sources/2026_assorted_2d_rc_experiments.md#hybrid46-raylib-port)); IceKontroI's 8-neighbour flood runs jumps from 2048 down to 1, 12 passes at 1080p rounded up to even, in about 0.75 ms on an RTX 2080 Ti ([Bevy](../sources/2024_bevy_2d_rc_repositories.md#icekontroisparse_rc_2d)).
- **Ping-pong parity.** nixonyh's last step-1 pass never reaches the distance field, and Sohojoe's distance pass reads the second-to-last pass's output ([Bevy](../sources/2024_bevy_2d_rc_repositories.md#nixonyhbevy_radiance_cascades), [Godot 2D](../sources/2024_godot_2d_rc_repositories.md#godot-integration-patterns)).
- **Empty seeds.** A seed stored as `(0, 0)` cannot be told from "no seed": jason.today's unseeded pixels measure their distance to the UV corner, clamped to 1, and partial runs can leave pixels unseeded; the community demo stores `(−1, −1)` for "none" and treats a seed exactly at `(0, 0)` as empty; read from the code, Hybrid46's unseeded texels get a finite distance to the origin instead of "far" ([jason.today part 1](../sources/2024_mcghee_building_realtime_gi_part1.md#observations-from-the-code-not-stated-by-the-source), [demo](../sources/2026_rc_community_site_and_wiki.md#distance-field-seed-jfa-df)).
- **Precision.** Positions need 16 bits: GM Shaders packs each coordinate into two 8-bit channels (`r = floor(255f)/255`, `g = fract(255f)`, decoded as `r + g/255`, the same code in both versions; precision about 1/65025, values up to about 1.0039), which is 16-bit fixed point in an 8-bit target, while plain 8-bit fields fail ([GM Shaders](../sources/2024_yaazarai_gmshaders_radiance_cascades.md#distance-field-and-jfa-both-versions), [layout formats](cascade_layout_and_merging.md#formats)).
- **Units.** Fields in UV units are anisotropic on non-square screens (jason.today's GI demo, qJay44); GM Shaders' optimized build divides the pixel distance by the render diagonal so the value fits its 2-byte encoding and stays isotropic ([GM Shaders](../sources/2024_yaazarai_gmshaders_radiance_cascades.md#raymarching-post-version)).
- **Unsigned fields.** A jump flood gives distance to the nearest occupied pixel, not a signed distance; kiss3d biases the field outward by two pixels so grazing rays do not tunnel through thin occluders ([assorted 2D](../sources/2026_assorted_2d_rc_experiments.md#kiss3d-decoupled-cascades)), and TypeGPU's default tracer shrinks obstacles by `erodeBiasProbes` probe spacings instead (below).

**Opacity per sample against opacity per length.** Several fixed-step marchers apply a constant opacity per sample: wfyyDz and its forks (1% per sample whatever the step, an optical depth of about 0.20 per pixel at level 0 and 0.008 at level 5, a factor of about 24), knowdawg (`T *= exp(−a)` per sample), tmpvar's playground (the step size is passed in and unused) ([Shadertoys](../sources/2023_rc_shadertoys.md#ffl3rf-codyjbennett-hardware-bilinear-without-the-fix), [Godot 2D](../sources/2024_godot_2d_rc_repositories.md#knowdawg-scene-mip-pyramid-per-cascade), [playground](../sources/2024_tmpvar_rc_playground.md#raymarch)). Since cascades march with different steps, and the bilinear fix's four rays with different lengths, the same absorber then attenuates differently per cascade and per ray (derived). The codes that scale by length use `exp(−σ·s)` (kornelski, CoreCascade, TypeGPU's holographic runner, amitabha) or the opacity correction `A = 1 − (1 − A0)^(s/s0)` for a step `s` against the reference step `s0` (GPU Gems, chapter 39, which writes the exponent with sampling rates as `s0/s`), named by tmpvar for cascades marching coarser volumes ([blog posts](../sources/2024_rc_blog_posts_and_slides.md#tmpvar-implementation-notes), [volumetric RC](volumetric_and_radiative_transfer.md)).

## Libraries and engine projects

### TypeGPU (Software Mansion)

`@typegpu/radiance-cascades` 0.12.1 (0.12.2 at commit 7af6a9e, last package commit 2026-10-12) is a WebGPU library with an SDF runner and a holographic runner, created with `create`, recomputed with `run()` and exposing an `output` texture the app samples (with `size` and no `output`, `create` returns a `RadianceCascadesExecutor` (with `output`, a `RadianceCascadesExecutor<TOutput>`) whose output is a `RadianceTexture & SampledFlag`; a supplied `output` is a `TgpuTexture`, rgba16float with storage and sampled usage, or a write-only storage view); all GPU code is TGSL (`'use gpu'` functions compiled by unplugin-typegpu), with no hand-written WGSL ([TypeGPU](../sources/2026_software_mansion_typegpu_radiance_cascades.md)). The holographic runner and the drawing and gallery examples built on it are in [holographic RC implementations](holographic_rc_implementations.md#typegpu-holographic-runner). Source files at commit 7af6a9e, under `packages/typegpu-radiance-cascades/`: `src/index.ts` (12 lines) exports `create`, the deprecated `createRadianceCascades`, the slots `sdfSlot`, `emissionSlot` and `rayMarchSlot`, `defaultRayMarch`, `RayMarchResult`, `maxRayStepsAccess`, `rayMarchStepSafetyAccess` and the types `BaseStoredRayDim` and `MergeMode`; `src/runner.ts` (311) holds the SDF `create()` with the option defaults at lines 118-124, the tracing constants at 139-142, the two ping-pong cascade textures, the top-down cascade passes and the build pass, and exposes `run`, `with`, `initSync`, `initAsync` and `destroy`; `src/cascades.ts` (434) holds `getCascadeInfo` (43-107), `defaultRayMarch` (138-162, step cap at 145, hit test at 152, step at 156), the segment trace (164-183), the layer parameters (185-196), the bind group (198-203), `traceHardwareMergeRay` (225-256), `bilinearWeight` (258-263), `traceBilinearFixMergeRay` (293-313), `rayDirection` (315-321), `cascadePassCompute` with the 2 × 2 pre-average (326-379) and `buildRadianceFieldCompute` (394 on); `src/holographic/index.ts` (448), `layout.ts` (26) and `transport.ts` (73) hold the holographic runner; the 78-line README has a quick start for both APIs and documents `sdfResolution` at lines 46 and 63-64. The tests `tests/cascades.test.ts` and `tests/holographic.test.ts` were not read. The package never cites the 2023 RC paper.

**Inputs.** The required options are `root` (`TgpuRoot`), `sdf` (`(uv: v2f) => f32`), `emission` (`(uv: v2f) => v3f`), `sdfResolution` (`{ width, height }`, both above 0) and `size`, unless `output` reports its size. `sdf(uv)` is a signed distance (positive outside, negative inside) with the scene's shorter side as 1, so 10 px in a 1024×512 scene is `10/512`; `emission(uv)` is linear RGB emitted light, not material colour, zero for plain obstacles and allowed above 1. `sdfResolution` is the distance texture's size or, for an analytic SDF, the wanted surface detail; it allocates nothing and only sets tracing tolerances. `size` is the lighting texture, which can be smaller than the canvas (a smaller one costs less and resolves less detail), and `renderAspect` (default output width over height, which must be above 0) must be set when the lighting texture's aspect differs from the scene's: a square lighting texture over a 1024×512 scene needs `renderAspect: 2`. The built-in tracer treats surfaces as opaque; reflection and bounces are left to the app.

| Option | Default | Meaning |
|---|---|---|
| `maxRaySteps` | 64 | steps per ray, a positive integer |
| `stepSafety` | 1 | step multiplier in `(0, 1]` |
| `erodeBiasProbes` | 1 | shrinks every obstacle by this distance; at least 0 |
| `epsProbes` | 0.25 | hit tolerance; at least 0 |
| `minStepProbes` | 0.125 | minimum step; at least 0 |
| `baseStoredRayDim` | 1 | 1, 2 or 4: 4, 16 or 64 rays per lighting sample at the finest level, independent of `size` |
| `mergeMode` | `'hardware'` | "the faster interpolation path", or `'bilinear-fix'` with "extra visibility checks to reduce light leaking at a higher cost" |
| `rayMarch` | `defaultRayMarch` | custom tracer for both merge modes |

The three `…Probes` distances are in finest-probe spacings, `1/min(baseProbes)` scene units. Each doubling of `baseStoredRayDim` doubles the internal textures per axis, and at 4 a lighting texture with a 4096 px diagonal exceeds the default 8192 px limit, the guide's claim, consistent with the `cascadeDim` formula below. A custom `rayMarch(origin, direction, startT, endT, eps, minStep, bias)` returns `RayMarchResult({ color, transmittance })` with accumulated linear colour and transmittance from 1 (clear) to 0 (opaque), positions `origin + direction·t` in scene units; `maxRaySteps` and `stepSafety` apply only to the built-in tracer.

**Image scenes.** The guide's image-based scene runs `@typegpu/sdf`'s `createJumpFlood` over an rgba8unorm 2048² source whose alpha marks solid pixels (`classify` reads alpha above 0.5), returns `signedDist/min(size)` as the SDF and the source RGB with alpha 1 as colour, sets `sdfResolution` to the flood size with a 512² preview, and calls `updateLighting()` (flood, then lighting) again after each edit of the source image.

**Constants.** From output `W×H`, `diag = hypot(W, H)`: `P = max(16, 2^floor(log2(diag)))` base probes on the longer axis and the shorter axis scaled by the aspect, `B = [P, max(16, round(P/aspect))]` when `aspect ≥ 1` and `[max(16, round(P·aspect)), P]` otherwise; `interval0 = 1/min(B)`; `maxRange = hypot(a, 1)/min(a, 1)` for render aspect `a`; `N = max(5, ceil(log2(3·maxRange/interval0 + 1)/2))`; each cascade texture is rgba16float of `cascadeDim = max(B·base, base·2^(N−1))` per axis. Layer `L` has `max(1, floor(B/2^L))` probes per axis, `R_L = base·2^L` stored directions per axis, a valid region `validDim_L = probes_L·R_L` that never exceeds `cascadeDim`, `(2R)²` actual rays per probe, and the interval `interval0·(4^L − 1)/3` to that plus `interval0·4^L`. Shared tracing constants: `eps = max(1/min(Sw, Sh), epsProbes/min(B))`, `minStep = max(0.5/min(Sw, Sh), minStepProbes/min(B))`, `hitBias = erodeBiasProbes/min(B)`.

| Layer at 512² | Probes per axis | Stored directions per axis | Rays per probe | Interval (scene units) |
|---|---|---|---|---|
| 0 | 512 | 1 | 4 | 0 to 1/512 |
| 1 | 256 | 2 | 16 | 1/512 to 5/512 |
| 2 | 128 | 4 | 64 | 5/512 to 21/512 |
| 3 | 64 | 8 | 256 | 21/512 to 85/512 |
| 4 | 32 | 16 | 1024 | 85/512 to 341/512 |
| 5 | 16 | 32 | 4096 | 341/512 to 1365/512 |

Every layer has 512² valid texels, so each pass dispatches 64×64 workgroups of 8×8. In general a layer dispatches `ceil(validDim/8)` groups of 8×8 per axis, with threads outside `validDim` doing nothing, and the build pass `ceil(W/8)` by `ceil(H/8)`.

**Passes.** `N + 1` compute dispatches in one compute pass: layers from `N − 1` down to 0 (the pipeline array is reversed after construction), then a build pass. Layer `L` writes texture A when `N − 1 − L` is even and B otherwise, reading the upper layer from the other; the top layer and the rest share `cascadePassCompute` with different slot values. A layer binds a uniform `CascadeLayerParams` (probes, upper probes and valid size as `vec2u`; `raysDimStored`; `startT`, `endT`, `aspect`, `eps`, `minStep`, `hitBias`), the upper texture, a linear sampler (linear magnification and minification, default address modes) and a write-only rgba16float storage texture.

**Per thread.** Direction `d = g mod R` and probe `p = floor(g/R)`, so nearby threads share a probe while storage stays direction-major (texel `d·probes + p`), as the comment says: "Group nearby directions for tracing locality; keep texture storage direction-major." The four actual rays of stored direction `d` are `2d + (i & 1, i >> 1)`, numbered `k = morton2D(…)`, at `θ = (k + 0.5)/(4R²)·2π − π`, direction `(cos θ, −sin θ)` with x divided by the aspect when it is at least 1 and y multiplied by it otherwise, so directions are unit length in shorter-side units. A ray whose probe leaves the unit square before the interval starts contributes `(0, 0, 0, 1)`. The stored value is the mean colour and mean transmittance of the four rays.

**Tracing and merge.** The default march stops at `sdf + bias ≤ eps` with the emission and transmittance 0, steps `max(hitDist·stepSafety, minStep)`, and returns colour 0 and transmittance 1 when `t` passes the end; the positive bias shrinks obstacles. The top layer, with no upper layer, only marches `[startT, min(endT, exitT)]`. The hardware merge marches the same span, where `exitT` (from `rayBoxExitT`) is the distance from `probePos` to the unit-square boundary along the direction, and, if transmittance exceeds 0.01 and the ray does not leave the domain within the interval, samples the upper tile `dirActual·probesU` at `clamp(probePos·probesU, 0.5, probesU − 0.5)` with linear filtering at mip level 0, combining `near.color + up.rgb·near.T` and `near.T·up.a`. The bilinear-fix merge takes `samplePos = clamp(probePos·probesU − 0.5, 0, probesU − 1)`, `base = floor(samplePos)` and `f = samplePos − base`; each corner `c ∈ {0, 1}²` takes `upperProbe = min(base + c, probesU − 1)` and weight `(1 − f.x or f.x)·(1 − f.y or f.y)`, and a corner with positive weight finds `upperProbePos = (upperProbe + 0.5)/probesU` and its domain exit `upperExitT = rayBoxExitT(upperProbePos, dir)`, traces from `probePos + dir·startT` to `upperProbePos + dir·endT` (through `traceSegment(start, end, aspect, eps, minStep, bias)`, which converts the UV delta to a unit direction and calls `rayMarch` with start 0), and, if transmittance exceeds 0.01 and `upperExitT > endT`, reads the upper texel with `textureLoad` (no filtering) and accumulates it by weight.

**Output.** The build pass binds a uniform `BuildRadianceFieldParams` (`probes: vec2f`, set to `B`), the `src` texture, `srcSampler` and the `dst` storage texture; for pixel `g` it takes `uv = (g + 0.5)/(W, H)` and `probePixel = clamp(uv·B, 0.5, B − 0.5)` and sums `base²` linearly filtered layer-0 samples at `probePixel/textureSize + (x, y)·uvStride` with `uvStride = B/textureSize`, one sample in each direction tile of the direction-major layer, and writes their mean with alpha always 1, so transmittance is not exposed. Read from the code: `eps` cannot fall below one SDF texel and `minStep` below half of one, while the probe terms come from the output size, so the SDF floors win when the SDF is coarser than four times the probe count (a 512² output over a 512² SDF gets `eps = 1/512`, four times the probe term; over 4096² it gets `0.25/512`), and features thinner than half a texel can be stepped over.

The three examples live in `apps/typegpu-docs/src/examples/rendering/`, each with a `meta.json` holding a title, a description, the category `rendering`, tags and `coolFactor` 8. **The from-scratch example** (`radiance-cascades`, titled "Radiance Cascades", "Demonstrates real-time 2D global illumination by tracing and merging progressively larger radiance cascades") does not use the package; its file header says so and points to the package guide and the drawing example. Its scene (`scene.ts`, where `sceneSDF` returns distance and colour) has three emissive disks (red, green, blue, radius 0.05), two emission-free boxes and a grey disk of radius 0.1 in UV units, in a `SceneData` uniform struct. Output probes `min(canvas.width, maxOutputResolution)` with `maxOutputResolution = 1024` (the radiance field is a square texture of `outputProbes` per side), cascade probes `2^round(log2(diag·0.35))` with `diag = outputProbes·√2` (`LIGHTING_RESOLUTION` 0.35), square cascade textures twice the probe count, count `ceil(log2(1.5·3/interval0 + 1)/2)` with a fixed range of 1.5 and no minimum of 5, two ping-pong texture arrays with one layer per cascade, `raysDimStored = 2 << L`, a 64-step march with `eps = 0.5/base` and `minStep = 0.25/base` and no erode bias or step safety, a linearly filtered upper sample whenever `T > 0.01` and `layer + 1 < cascadeAmount`, with no domain-exit check, a 2×2 final gather of layer 0 texels in `probes` units averaged by 0.25, and ACES display with an SDF-smoothstep surface alpha and an overlay debug view. A comment notes that "Ray intervals are distances in normalized scene space, not texture UV coordinates."

### Bevy

Four Rust and WGSL projects, none with temporal reuse, bounce light or timings except IceKontroI's slides ([Bevy](../sources/2024_bevy_2d_rc_repositories.md)).

- **nixonyh/bevy_radiance_cascades** (Bevy 0.14, no license, 2024-08). Occluders drawn into an R16Uint mask, a jump flood, an R16Float distance field, cascades top-down in two screen-size Rgba16Float ping-pong textures, a probe-average mip and a fullscreen add onto the HDR image. Position-first `w×w` probe blocks with `w = 2^(c+1)` and one ray per texel, so every cascade has `W·H` rays; intervals `[0, 2], [2, 10], [10, 42], …` (`i0 = 2`); count `min(16, ceil(log4(1 + 3D/i0)))`, the smallest whose summed intervals reach the diagonal, 6 at 1080p. At most 32 sphere-tracing steps; emitters are texels above 1.0 and a hit returns `sign(c)·max(|c| − 1, 0)`, so negative light works. Hits skip the merge; misses read 4 upper probes × 4 rays (16 texels) with parity weights 0.75/0.25, times 0.25, and no ringing fix. Two bugs from reading: the flood's last step-1 pass never reaches the field (a ping-pong parity off-by-one), and the probe-average mip divides by `2w` instead of `w²`, correct only at the default `w = 2`.
- **kornelski/bevy_flatland_radiance_cascades** (0.16, CC0, 2025-09). Rays ×2 per cascade with spacing ×2 (branching factor 1), 16 merged directions at cascade 0, probes 2 px apart, 6 cascades, intervals doubling from `[0, 16]`; direction-first compute buffers pre-averaging 2 raw rays; a fixed-step volume march with `exp(−extinction·density·step)`, so its alpha is a transmittance and the merge is `traced.rgb + traced.a·upper`, taking `min(L, (L + 10)/2)` samples per interval; interval ends staggered about ±10% to hide cascade edges. The README names a "gear fix" ([artifacts](artifacts_and_fixes.md#cheaper-fixes)) only once, as a workaround that reduces halos at cascade seams in place of the bilinear fix, and no code uses the word. The merge reads four upper texels from `(probe − 1)/2` with fixed weights per axis, 1/3 on the lower neighbour for even probes and 2/3 for odd, under the comment "cascades are never perfectly aligned"; with probes at `(i + 0.25)·s` on every level the geometric weights on the lower neighbour would be 1/8 for even and 5/8 for odd indices (probe 2 at 2.25 s lies 7/8 of the way from upper probe 0 at 0.5 s to upper probe 1 at 2.5 s; derived), so the fixed weights are a deliberate blur toward the lower neighbour, strongest on even probes. A doc comment still says "no pre-averaging yet" and "no bilinear fix" while the shader pre-averages, and the hardware-filtered fetch is not implemented.
- **Lommix/solis_2d** (0.15, MIT/Apache, 2025-01). Fullscreen fragment passes (SDF, ping-pong cascades, probe-average mip, composite); direction-first `2^c × 2^c` blocks, each the size of the probe grid, with 4 raw rays per texel (`4^(c+1)` per probe), so pre-averaging is built in; the one-fetch merge at `probe·0.5 + 0.25` clamped half a texel inside the block; intervals from `i0·(4^c − 1)/3` to `i0·4^c` with `i0 = 6`; at most 16 sphere-tracing steps; normal maps multiplying by `N·L` at cascade 0 with a configurable light height; an edge highlight `light/|sdf|` with no guard against zero distance.
- **[IceKontroI/sparse_rc_2d](https://github.com/IceKontroI/sparse_rc_2d)** ([slides](https://docs.google.com/presentation/d/1shDaU-fOrhVIg4lGkITJcxVnf-VkVVTahlxngPiqeMs/edit?usp=sharing); 0.17-dev, MIT/Apache, 2025-09). A test bed for sparse cascades meant for 3D ("a work in progress"), every pass written from scratch on the author's own GPU wrapper inside Bevy's render graph, with slides. Three modes share the march and the merge: SparseFilled (default, a probe at every non-solid texel, output identical to Dense), SparseEdge (probes only next to edges) and Dense.
  - Shared: probes ×2 apart (`PROBE_SPACING = 2`; other values break it), rays ×4, no interpolation, no bounces, count `min(32, ceil(log4(|dims|)))` (6 at 1080p), dense storage of `dims/2` rounded up to a multiple of `2^N` (960×576 at 1080p) with cascade 0 lighting written at half resolution.
  - Layout: level `c` has spacing `2^(c+1)` px and `4·4^c` rays in a direction-first `2^c × 2^c` grid of blocks, one texel per probe and group of four rays; pre-averaging is folded into the values (`rgb·0.25` on hits, `0.25·parent` on merges, added only when the ray is unoccluded); the parent is the same block at `coord/2`. Intervals start at `2·(4^c − 1)/3` (0, 2, 10, 42, 170, 682 px) with length `2·4^c`; a comment lists `2·4^c − 1`, which is stale.
  - March: sphere tracing an unsigned field sampled at `round(pos)` from `start + 0.5` toward the parent ray's target, with no step cap beyond bounds checks; a hit is `d ≤ 0.5·√2` and takes the brightest of the 2×2 emissive texels. The nearest-neighbour fix aims child rays at index 1.5 of the parent group, the centre of the four parent rays, after a GM Shaders shader; the forking variant (Space key) "seems to introduce blind spots" and is off by default.
  - Field: texels with nonzero alpha seed an 8-neighbour flood with jumps from 2048 to 1, 12 passes at 1080p (rounded up to even), about 0.75 ms on an RTX 2080 Ti; the field, lighting texture and mouse drawing stay dense in every mode.
  - Sparse seeding: each workgroup owns a 64×64 tile at 1080p (30×17 workgroups) and walks its 4096 texels in Z-order, 256 at a time; a task is `texel/2`, so four consecutive Z-indices map to one probe. SparseEdge classifies 2×2 quads as empty, mixed or solid (solid when `ceil(alpha) = 1`) and places a probe when a diagonal quad is mixed or the diagonal quads include both empty and solid. A ray that misses adds its parent as a task for the next cascade; siblings are adjacent in Z-order, so comparing each entry with the three before it ("3-left") removes duplicates without a hash.
  - Slab chains: per-cascade linked lists of 256-entry slabs, with the heads and lengths of 32 chains in workgroup memory; slabs come two at a time from an atomic counter out of a 64,000-slab pool allocated once (8 B of coordinates and 4 B of colour per entry plus a 4 B next pointer per slab, about 197 MB); a colour packs 8-bit RGB with a flag byte of four per-direction hit bits and four uniqueness bits. An exhausted pool counts the loss and drops tasks, and a comment says too few slabs flicker. The merge runs top-down from the highest level reached (tracked by `atomicMax` while casting), each child finding its parent through a prefix-sum index.

The sparse memory figure counts 16 B per slab where a slab takes 3,076 B, 192 times more, so Star SparseFilled's 0.24 MB is about 15,000 slabs, about 46 MB, ten times Dense's 4.42 MB for two RGBA8 textures of 960×576 (derived): the time and ray savings stand, the memory saving does not. Planned: sparse transmissive RC with probes only on emissive voxels, rays culled below an emission threshold, no merge path and hash-bucketed writes against the many-to-one write race; an omnidirectional shadow map for sky light, called "highly experimental"; and for 3D a precomputed seed chain or sort, with Z-order and direction-major iteration keeping the dedupe hash-free. **YMM4-Radiance**, a 2D lighting effect for the YukkuriMovieMaker4 video editor in four Direct2D pixel shaders: emission, a 9-level occupancy pyramid (2×2 max, stored as horizontal stripes), cascades 3 to 0 with cascade 0 cached, and a composite; the README says the load is high and gives no measurements. Four levels at 2, 4, 8 and 16 px with 4, 16, 64 and 256 directions; bounds `[0, 1, 5, 21, 85]/85` of a 300 px range (0 to 3.5, 17.6, 74.1 and 300 px); output padded by the range on every side up to 4096 px. Emission is `saturate((lum − th)/(1 − th))²` from Rec.709 luma, with alpha the absorption density. The walk skips empty space from the 8 px level: an empty cell jumps to its exit plus 0.05 px and moves up a level, an occupied cell moves down; at the finest level it steps `clamp(0.03·t, 1, 32)` px, gathers `T·emission·gain·h/(t + 2)`, applies `T *= exp(−0.6·alpha·h)` and stops at `T ≤ 0.004` or 128 iterations, returning a partial result without a flag. The merge averages 4 upper directions by hardware filtering at `(x − worldL)/(2·spacing) − 0.5` and saturates `gather + T·upper`, clipping HDR light; the composite lights surfaces by `light·albedo·diffuse` and adds `light·(1 − diffuse)` as glow in air; no bounce. Defaults (ranges): strength 100 (0 to 800), range 300 px (10 to 2000), diffuse 60, ambient 100, threshold 70, gain 150 (0 to 1600), occlusion 80; the README's ranges are narrower, the changelog says near levels use finer directions (the opposite of the code), and one gain uniform is unused ([repository survey](../sources/2026_rc_repository_survey.md#ymm4-radiance-video-editor-effect)).

## CPU references and research harnesses

- **CoreCascade** (Go, CPU, MIT, 2025-10): one image per run with plain RC, RC with the bilinear fix, light propagation volumes or a path tracer, a ready comparison harness; main has 2D, an experimental 3D renderer, directional emitters and float32; the `absorption` branch is 2D only in float64 with unused OKLab code and a README line on light propagation with no code behind it; the absorption model, cascade geometry and merge are the same on both branches. The README says the method would run in real time on a GPU, unmeasured, and that most implementations zero the probes outside the image, which is usually enough. Media: emission per unit length `E`, one absorption `σ` and a diffuse tint used only for re-emission; each step adds `vis·(E/σ)(1 − e^(−σs))` (or `vis·E·s` for `σ ≤ 10⁻⁴`), stopping at `vis < 10⁻⁴`; walls are strong absorbers and emitters volumes whose brightness grows with path length inside them. SDF shapes are sphere-traced with `step = max(|d|, 0.01)`, integrating only inside shapes, for at most 128 steps (both branches stop silently there); grid scenes take fixed `2/W` steps with nearest samples. Geometry: the scene spans `[−1, 1]²`, cascade 0 spacing `2/W` with interval `L0 = 1/W`, count `ceil(log4(2√2/L0)) + 1`, directions ×4 from 4, spacing ×2, grids `N_i = ceil(N_(i−1)/2) + 1` per axis with the first probe moved back a quarter of the upper spacing so upper probes cover the edges, contiguous intervals `[L0·4^(i−1), L0·4^i]`. The merge is `color += far.color·near.vis`, `vis *= far.vis`, with four far directions under weights `0.25 + 0.5·(x & 1)`; the fix traces from `probe + dir·TStart` to each far probe's `far + dir·TEnd_near`. A second pass feeds fluence times diffuse colour back as emission for one more bounce, with nothing keeping diffuse at or below 1 (the absorption branch's absorber has diffuse 3, black on main). At 800×800: 7 traced cascades plus an untraced eighth, grids 800, 401, 202, 102, 52, 27, 15 and 9 probes wide, intervals from `[0, 0.00125]` to `[1.28, 5.12]` scene units, 19.8 M probe directions, so 19.8 M rays plain and 79.4 M with the fix, and 805 MB of cascades at 32 B per entry in float64 or 403 MB in float32, 170 MB of it the untraced level (derived). Bugs from reading: the fix tests only whether the near cascade is the last, so cascade 6 traces toward cascade 7 and merges its never-computed values (black, visibility 1), adding rays and no light; merged visibility starts at 1 and sums four directions before dividing by 4, giving `(1 + Σv)/4`, 1.25 in empty space, though stored visibility never reaches colour; the path tracer runs 101 samples and divides by 100; output is Reinhard with a 1/2.2 power, not the sRGB curve; a comment calling visibility a hit flag is stale; on the absorption branch the SDF march adds its last step whole past `tmax` and the grid march does not clip to the scene bounds, while main clips both ([assorted 2D](../sources/2026_assorted_2d_rc_experiments.md#corecascade)).
- **Peter's bachelor thesis** ("Performante globale Beleuchtung durch Radiance Cascades", Robert Peter, Hochschule Hannover, 14 May 2026; code MIT, thesis CC BY 4.0; C++, OpenGL 4.5 compute): spacing ×2 and directions ×2 per cascade, 4 rays per probe at one probe per pixel, 9 cascades in the timings and 8 elsewhere and in the code, a base interval of one pixel diagonal, `t_min = t0·(f^c − 1)/(f − 1)`, bilinear merge, SDF circles and boxes sphere-traced up to 128 steps, the normalized hit distance stored in alpha (0 for empty), one RGBA16F atlas eight times the image (15360×4320 at 4K), timed with OpenGL timestamps (200 warm-up frames, median of 1000) on an RX 7900 XTX. Its per-pass results are in [performance](performance.md); its merge-kernel test, whose 3×3 kernel sits behind a `BLUR` define the repository never sets, in [artifacts](artifacts_and_fixes.md#grid-and-blocky-penumbras). Limits: point emitters, no BRDF or bounces, no memory or error measurement, FPS figures for the kernel comparison that do not match its frame times, a merge that reads and writes one atlas in place, and a never-set flag array that skips the atlas copy when filtering is on ([Peter](../sources/2026_peter_rc_2d_bachelor_thesis.md)).
- **Gigi graph** (Kosmokleaner, Martin Mittring per `Technique.json`, BSD-3, 2026-10): nine HLSL passes in EA's Gigi (paint, occupancy, one propagate pass per cascade from 5 to 0, final): an RGBA16F emission-opacity scene, an 8×8 occupancy grid for skipping, 6 cascades at 512² direction-first with 4 rays pre-averaged per texel, ray `j` at `(j + 0.5)·2π/count`, and each cascade its own texture, intervals `[0, s)` then `[s·4^(c−1), s·4^c)` with the top marching `[256, 1024)`, front-to-back marches with bilinear scene reads accumulating `L += T·rgb·a`, `T *= 1 − a` and stopping at `T < 0.01` or the texture edge, the bilinear fix (the four upper probes around `o/(2T) − 0.5`, clamped, each with its own march, which a source comment says avoids both double counting, seen as bright rings, and gaps, seen as leaks), a final albedo of 0.5, and an ambient term commented out while debugging because it "hides leaks"; the repository has no timings ([Gigi](../sources/2026_gigi_and_volume_rc_repositories.md#gigi-2d-rc)).
- **amida** (entropylost, Rust on LuisaCompute): 512² plain RC, 1 px cascade 0 with 4 directions, ends `4^L` px, 6 cascades, pre-averaged (each stored direction the mean of its 4 children). Four merges all trace from the probe's interval start to a chosen upper probe's interval end: single stochastic (1 ray, one corner per axis picked by comparing a fixed random number with the bilinear fraction), nearest (1 ray), bilinear fix (4 rays, all corners) and diagonal (2 rays, the diagonal pair picked by the fraction's quadrant, weights in the style of `(t.x + t.y)/2` so each pair sums to 1); the README says the fix is 4× slower than the single-ray variants. A second cascade set computes diffuse bounces at half resolution (2 px spacing, 16 directions, starts at 1.5 px) with the stochastic merge, since the code comment saw no difference between variants for bounce light; the top cascade samples an environment map pre-averaged into its bins; a pixel DDA skips unchanged 8×8 blocks through a per-block 64-bit mask of pixels that differ from a neighbour; transmittance exits below 0.001 ([2D references](../sources/2025_hrc_and_2d_reference_implementations.md#amida-merge-variants-compared)).
- **Adrian Margel's nested RC** (WebGL2, 2024-10): each level-`L` cell (`2^L` px) has `4·2^L` probes on a circle of radius `2^L·√2/2` around its centre, each with `4·2^L` rays running to where they leave the next level's circle and merging with the average of the next level's rays inside its cone; the gather interpolates the four level-0 probes at each pixel's corners by the angle each covers. Interval ends follow geometry instead of fixed lengths, but rays sample only every 5 px, so the lower levels sample only their start points ([2D references](../sources/2025_hrc_and_2d_reference_implementations.md#adrianmargel-nested-rc)).

## Setups that worked in 2D

From implementers' reports ([merging notes](../sources/2026_merging_and_ringing.md#scaling-and-setups)):

- **Notation.** `2x/4x` means spacing ×2 per axis and directions ×4 per cascade, keeping every cascade the same size; `2x/2x` halves each cascade, so the total stays under twice cascade 0; some write the spatial factor in area, so 2x/4x becomes 4x/4x.
- **Defaults.** One probe per pixel, 4 cascade 0 rays of length about `√2` (1.4 to 2 px), ×4 intervals, about `log4` of the diagonal cascades (about 5 at 512², rarely more than 6), interval scaling matched to angular scaling.
- **2x/3x** costs a fraction of 2x/4x for similar quality with the bilinear fix and was preferred on a Steam Deck; memory is 2.75× cascade 0; three cascade 0 rays may show moiré.
- **2x angular branching** needs about 32 cascade 0 directions and 16 to 32 px first intervals, looks poor without them, and ran out of memory at 32 rays in one report; switching from 4x to 2x after about 64 directions suits large scenes.
- **Higher branching** (8× and up) is sharper at equal memory and suits cheap per-ray methods such as line sweeping; 16× looks bad without cascade −1; two cascades at 64× were sharper than 4× but slower.
- **Probe reduction** of at most half per axis per cascade; quartering aliases heavily.
- **Low resolutions** (240p to 360p pixel art) suit HRC, or RC above output resolution scaled down.

**A shipped 2D game** (Switch target) used three 2x/2x cascades, C0 384×256×4, C1 192×128×8 and C2 96×64×16, in 3D textures with the angle on Z (repeat wrap, hardware filtering). Each cascade reads a progressively downsampled scene with one fetch per direction, weighted by `pow(2, i²)` per cascade to keep the single fetch from leaking (others argued 12 fetches are needed), and a Gaussian after downsampling stabilized it. RC carries indirect light only; point lights are direct, shadowed by marching a GI depth buffer ([merging notes](../sources/2026_merging_and_ringing.md#scaling-and-setups)).

## Connections across implementations

- **A convergent design.** By late 2024 most codes outside Shadertoy had settled on the same layout: direction-first, pre-averaged groups of four, one hardware-filtered merge fetch at `p/2 + 0.25` clamped inside the tile, and two ping-pong textures with one pass per cascade from the top. GM Shaders' optimized build, jason.today, the community demo, Lommix's solis_2d, Youssef-Afella and its Hybrid46 port, qJay44, tsukinousagi18, 3cKczD, ffl3Rf, NfySzt and TypeGPU's hardware mode all use it ([2D articles](2d_articles_and_demos.md), [2D Shadertoys](2d_shadertoys.md)). Sohojoe's port of the same layout reads with `imageLoad`, which loses the filtering and turns the merge into nearest-neighbour, the one way the design fails silently (inference, from the sources above).
- **The testbed line went the other way.** Suslik's line moved from fad's capacity-derived grids and 16 pre-averaged directions to fixed grids, 4 directions, the bilinear fix by default and mean output, and kept the 16-trace per texel position-first merge that the fix needs. The two families split on whether the merge can use hardware filtering: the fix cannot ([artifacts](artifacts_and_fixes.md#the-bilinear-fix)).
- **Precision failures repeat.** RGBA8 cascades or fields clip and band in the futureengine2 gist, Hybrid46, CptNemo0, IceKontroI's colour and Yaazarai's first port (gamma-space RGBA8, later RGBA16F); YMM4 saturates merged light; Peixoto relies on RGBA16F turning `1e20` into +inf. The codes that work store cascades in RGBA16F or R11G11B10F and positions in at least 16 bits ([layout formats](cascade_layout_and_merging.md#formats)).
- **Normalization is not shared.** Outputs are fluence (`×2π`), mean radiance, means of the nearest probe, or exposure-scaled values, so brightness differs by about 2π between otherwise similar codes ([layout](cascade_layout_and_merging.md#final-gather)).
- **Opacity per sample** makes several media codes depend on step count (above).
- **Single-frame is the default off Shadertoy.** Every non-Shadertoy 2D code computes its cascades top-down in one frame except where it reads back the previous frame on purpose: GM Shaders' original bounce, thmasn's SubViewport chain, LegitScript's one-pass atlas, kiss3d's default brute-force path, lixu0073's accumulation and CptNemo0's per-cascade rates. Feedback for bounces is the one temporal element that remains, and amida and CoreCascade show it can be a second cascade set or a second pass instead (inference).
- **Measured cost is scarce.** Of all the 2D codes, only Peter's thesis, IceKontroI's slides, [GM Shaders' stress test](2d_articles_and_demos.md#gm-shaders-yaazarai-and-xor) and a few README claims give timings; the rest are in [performance](performance.md).

## Single-frame assessment

For single-frame 3D RC (inference, from the sections above):

- 2D shows the whole pipeline running from scratch each frame, with no temporal reuse, at 0.7 to 8.7 ms from 720p to 4K (Peter's thesis, RX 7900 XTX) and 0.5 to 4.9 ms at 1080p (IceKontroI, RTX 2080 Ti), so the method itself needs none; the frame lags in Shadertoy and LegitScript come from the hosts.
- The one-fetch direction-first merge is the cheapest merge in 2D; its 3D analogue is in [layout](cascade_layout_and_merging.md#merge-kernels). It is incompatible with the bilinear fix, so a 3D design must choose between hardware interpolation and a visibility-correct merge per cascade.
- Scene representations that skip empty space (occupancy pyramids, block masks, mip pyramids) are what make long intervals cheap in 2D; the 3D counterparts are in [scene representation](scene_representation_and_tracing.md).
- Bounces in 2D come from feeding last frame's result back; a single-frame design needs a second cascade set or pass per bounce, as amida and CoreCascade do, or accepts one bounce.
- Sparse cascades (IceKontroI) cut rays 4 to 30× in 2D scenes with large empty or solid areas, and the slides' 3D plan (Z-order, hash-free dedupe) is a lead for sparse 3D grids ([3D world space](3d_world_space.md#hash-maps-for-probes)).
