# 2D Shadertoys

Shadertoy holds the reference 2D RC codes: fad's original, Sannikov's testbed line and its forks, and later independent builds. This topic records what each 2D shader does, read from its code (the shader data on shadertoy.com and the API dump at https://github.com/GabeRundlett/shadertoy-api-shaders, `shaders/<id>.json`), with its bugs ([Shadertoys](../sources/2023_rc_shadertoys.md)). Suslik is Sannikov's Shadertoy account; GM Shaders calls XcB3Ry Sannikov's gravity simulation. The shaders carry no license unless noted. Lineage and authorship are in [history and landscape](history_and_landscape.md#first-public-implementations-and-the-shadertoy-lineage), the parameters side by side in [cascade layout and merging](cascade_layout_and_merging.md#2d-parameters-across-implementations), the fixes' mechanisms and costs in [artifacts and fixes](artifacts_and_fixes.md), and the 2D codes outside Shadertoy in [2D implementations](2d_implementations.md).

Statements marked "derived" were computed from the code's constants; "inference" marks conclusions drawn here; "read from the code" marks behaviour found by reading, not by running.

## How Shadertoy shapes the code

Shadertoy runs each pass once per frame, with four buffers and one cube map, and a pass that reads a later tab gets that buffer's previous frame. So most shaders spread the merge over frames: either each cascade reads last frame's cascade above, which costs one frame of lag per level, or a ring of buffers computes a few levels per frame and refreshes the whole chain every two or three frames. The lags below assume passes run in tab order, Buffer A to D, then Image ([layout](cascade_layout_and_merging.md#tracing-and-merging-order)). 3cKczD and 33ycDm compute their result from the current frame, as do the single-cascade DlSfzz and NfVXRc; tf2XRc gathers every cascade in one pass but shows indirect light a frame late.

| Shader | Gather | Frames to settle |
|---|---|---|
| mtlBzX, clVcD3, XffcD7 | ×2π | 5 |
| DlSfzz | ×2π | 1 |
| mlSfRD | ×2π | 4 |
| MctXRr, 4ctXD8, MfXyRj | mean | 6 |
| lcfcR2 | mean of the nearest probe | 5 |
| wfyyDz, ffl3Rf | exposure ×2 | 2-frame ring |
| NfVXRc | extended gather | 1 |
| 3cKczD | mean | 1 |
| tf2XRc | mean | 2 |
| w3XSz4 | mean | about 10 |

The fad line multiplies the gathered mean by 2π to get fluence; the testbed line outputs mean radiance, as do 3cKczD, tf2XRc and w3XSz4. Both lines apply the tone map `1 − (1 + F)^−2.5`, so the same scene displays about 2π darker in the testbed line (derived).

## fad's line

- **mtlBzX** (fad, 2023-09-02). Passes for mouse smoothing, an SDF paint buffer (`.r` signed distance, `.gba` emission), a cube map holding every cascade, and the image; every cascade reads the previous frame's cube map. Five cascades: cascade 0 has 16 directions and about `6·W·H/17` texels' worth of probes, each cascade halves the probes per axis and has 4× the directions; cascade 0 stores the mean of its 16 rays per probe and each texel above the mean of 4, so cascade `n` stores `16·4^(n−1)` texels per probe. With `L0 = 4·|res|/(4^5 − 1)`, cascade `n` covers `[4^(n−1), 4^n]·L0` from 0 at cascade 0, so the top interval ends just past the screen diagonal. Sphere tracing takes at most 100 steps, a hit needs `t > 0.2` and `d < 1` px, and a ray starting inside a shape returns that shape's emission. Missed rays merge four upper probes at `pf = (p + 0.5)/2`, `q = round(pf) − 1`, `w = pf − q − 0.5`, then `rgb += a·S.rgb`, `a *= S.a`. The top cascade adds Mathis's sky integral over each ray's bin divided by the bin width and by 6, splitting bins that cross 2π ([core theory](core_theory.md#colour-space-and-range), NttSW7 below). The gather is bilinear over four cascade 0 probes, ×2π, tone-mapped, with emission linearized by `pow(c, 2.2)`. The header says small point lights ring and no fix was found; most forks keep the comment.
- **DlSfzz** (fad, the same day), mlSfRD's parent; "Debug" in the title, with no debug view or mode switch. Its constants make it one cascade: a fixed 320×180 grid, `c_dRes = 1` and `nCascades = 1`, one direction at angle π (pointing left) over `[0, 100]` px, a miss adding the sky average over the whole circle, so the merge never runs. The general code is fad's: cascade `n` uses the grid shifted right by `n`, traces `c_dRes·4^n` rays, stores 1 entry per probe at cascade 0 and `c_dRes·4^(n−1)` above, each the mean of its rays, intervals `[4^(n−1), 4^n]·c_intervalLength` with cascade 0 from 0, and a bilinear upper read with corner `floor(pf − 0.5)`. The diagonal-based interval length is computed and unused. Sky (0.2, 0.5, 1.0), a sun of 10·(1, 0.7, 0.1) at 2.0 rad, `S = 64`, added for misses only. The gather adds painted emission ×2π blended in by `clamp(3 − sd, 0, 1)` within 3 px of shapes. Space toggles emissive brushes and key 1 a temporary light; an idle Lissajous cursor paints strokes gated by `cos(time)`; Buffer B credits its Bézier SDF solver as the only correct one of many tried. Read from the code: the clipped exit test compares with a distance from the unclipped origin, so marches can overshoot the screen edge by the clip offset (the same lines are in mlSfRD, MfXyRj and lcfcR2); texels past the used range return without writing; the temporary light reads `screenRes` before `intersect()` sets it, so its radius may be zero on the first sample; cube reads use `texture()` on a direction, so results depend on sampler settings.
- **mlSfRD** (Suslik, 2023-09-04: "Original implementation by fad. I just fixed haloes."). Against DlSfzz it changes the constants (16 directions, 4 cascades, a 7 px interval, a 0.02 brush), adds the cross-faded interval ends and a hit distance in the trace result, and multiplies the sky by 0; merge, image (with its SDF overlay within 3 px of shapes) and paint passes are unchanged. Intervals `[0, 7], [7, 28], [28, 112], [112, 448]` px; the fade mechanism and its consequences are in [artifacts and fixes](artifacts_and_fixes.md#cheaper-fixes). The diagonal-based interval is still computed and unused, and the fade comment names only the 0-to-1 transition though the fade applies at every boundary. All cascades take `320·180·(1 + 4·3) = 748,800` texels, needing cube faces of at least 354 px (derived); the fixed grid makes the spacing 2.5 px at 800×450 and 6 px at 1080p while intervals stay in pixels, so the interval-to-spacing ratio changes with the window (derived).
- **clVcD3** (Quinchilion, 2023-11-23). mtlBzX's design with the grid axes rounded down to multiples of 32, `t1 = 4·diag/(4^N − 1)`, and direction fastest in memory, then probe x, then y. A fixed scene: a 10 px emissive disc orbiting on the emissive right half (`x ≥ 0.52·W` emits (2, 2, 2)) and a bar occluder; the mouse only draws a temporary light, while the header still describes drawing. Hits below 0.5 px. `RINGING_FIX`, the first mask fix, is in [artifacts and fixes](artifacts_and_fixes.md#cheaper-fixes); its bracket uses `floor(pf)` and `pf − q` without the centre offset while the merge uses `round(pf) − 1` and `w − 0.5`, so mask and merge disagree on probes and weights, probably by accident. The sky call is commented out. The gather overlays exact emission within about 3 px of shapes; a change takes about five frames to reach cascade 0.
- **XffcD7** (kornelski, 2024-07-17). mtlBzX with only the interval ends changed into gear teeth ([artifacts and fixes](artifacts_and_fixes.md#cheaper-fixes)); its comment says 1.1 works well while the value is 0.1, and at 1.1 the factor `1 − teeth` would be negative. Gather and schedule are fad's.

## The testbed line

- **MctXRr** (Suslik, 2024-04-19). Six cascades on a fixed 512×512 cascade 0 grid with 4 directions (`BRANCHING_FACTOR 2`; the inactive factor-1 branch has 256 probes, 16 directions and a `10⁻²·W` base). With `L0 = 10⁻³·W`, cascade 0 covers `[0, 4]·L0` and cascade `n` `[4^n, 4^(n+1)]·L0`, so the top cascade reaches `4.096·W`. Cascade `n` stores `4^(n+1)` texels per probe from 4 child rays each, `1024²` texels per cascade, one cube face (inference); cells are `W/512 × H/512`, not square on non-square windows. The merge traces from each child ray to each of the four upper probes, 16 traces per texel: the bilinear fix, with a plain trace per child still computed and discarded. The gather is the mean of 4 directions over 4 probes with no 2π; emitters use HSV value 1.5, a linear peak of about 2.4 against clVcD3's 0.6. Buffer A keeps a smoothed three-point mouse history, Buffer B draws quadratic Bézier strokes that nothing erases, and an idle Lissajous path draws blinking strokes. `RINGING_FIX` is defined with no reader, the ringing comment is stale, and `cubemapUsage`, `c_dRes`, `roundSDim` and `RAYS_FORK_POW` are unused; about six frames to settle.
- **4ctXD8** (Suslik, "RC Experimental Testbed", 2024-04-24). Six cascades, 4 directions and 512 probes across at cascade 0, `L0 = 0.0015·W`, interval starts `(4^k + 1)·L0` for `k ≥ 1`, every cascade the same texel count, each texel averaging its 4 upper directions, and the `MERGE_FIX` switch over six merges (0 vanilla, `CastMergedInterval`; 1 bilinear fix by default, `CastMergedIntervalBilinearFix`; 2 midpoint, `CastMergedIntervalMidpointBilinearFix`; 3 Dolkar mask, 4 parallax with ends stretched by 1.1, 5 inner parallax; [artifacts and fixes](artifacts_and_fixes.md)). `C_MINUS1_GATHERING` traces `[0, L0]` from every pixel per cascade 0 direction in the image pass, in front of the interpolated cascade 0 value ([layout](cascade_layout_and_merging.md#cascade-1-and-contact-detail)); the result is the mean over directions with no 2π.
- **MfXyRj** (Mytino, "Fork RC Testbed - circle proj", 2024-07-18), meant to show design patterns for RC (interpolation, packing, abstractions). 4ctXD8's layout with cascade 0 over `[0, 4]·L0` and cascade `n` over `[4^n, 4^(n+1)]·L0`, `L0 = 1.5·10⁻³·W`, so the top cascade ends at `6.144·W`; every cascade `2^20` texels, needing 1024² cube faces (derived). Each stored bin traces the 4 sub-directions of the cascade above and stores their mean; the top merges with `(0, 0, 0, 1)` and the sky functions are never called; the gather is bilinear over 4 bins and 4 probes with no 2π. Its four merge modes (vanilla; the bilinear fix, whose active `#if 1` block ends each ray on the circle around its upper probe, by default; midpoint; Dolkar mask) are in [artifacts and fixes](artifacts_and_fixes.md#straight-ray-fixes). In the circle mode the end is clamped to `max(t₊, t_start + 10⁻⁶)`, comparing a distance from the ray start with one from the probe, and at the default constants the clamp never acts; nothing guards the discriminant; the four bracketing upper probes lie within one upper-cell diagonal of the lower probe, about `0.0039·√(W² + H²)` at cascade 0, against a radius of `0.006·W`, so the discriminant stays non-negative for height-to-width ratios up to about 1.17 (derived). `MERGE_FIX 3` has its own trace body in which a start inside a shape returns `(0, 0, 0, 0)` at distance 0 while the other modes return the shape's emission, since the comment says the Dolkar variant works better when misses terminate. Read from the code: `intersect()` returns `t` instead of `tOffset + t`, so off-screen starts sample short and corrupt the mask's distances (DlSfzz returns the sum); no minimum `t`, so a probe within 0.01 px of an edge hits at once; the midpoint and mask modes use only the x spacing.
- **lcfcR2** (mxcop, "Fork RC MAX", 2024-07-18). mxcop is Max Coppen of [surfel RC](3d_surface_probes.md); "MAX" and the "by MAX" comments most likely mark Coppen's own changes (inference). It credits fad. Defaults `MERGE_FIX 3`, `SKY_INTEGRAL 0`, `PIXEL_PERFECT 1`, `MODIFIED_INTERVAL_SCALING 0`, 5 cascades, `BRANCHING_FACTOR 2`, `SPATIAL_SCALE_FACTOR 1`, a 512×256 grid with 4 directions and `L0 = 1.5·10⁻³·W`, cascade 0 over `[0, 4]·L0` and cascade `c ≥ 1` over `[4^c, 4^(c+1)]·L0`, the top cascade ending at `1.536·W`; a comment says the base length comes from the spacing while the code uses the width. Each cascade takes `2^19` texels, needing 661 px faces (derived); each lower texel averages four sub-directions `4k + s`, each from the selected cast, divided by 4. Its four casts (0, `CastMergedInterval`, marked work in progress, a circle fix with bilinear weights whose negative discriminant returns −1 and leaves a zero-length segment `normalize` cannot handle; 1, `CastMergedIntervalBilinearFix`, the bilinear fix; 2 the nearest upper probe, unweighted; 3, `CastMergedIntervalMaskFix`, active, one upper probe picked by a hash of the lower probe index with equal odds) are compared in [artifacts and fixes](artifacts_and_fixes.md#cheaper-fixes); the hash takes neither time nor direction, so the pick is a fixed white-noise pattern shared by every direction and by same-index probes of every cascade, and despite the shared name it is not the hit-distance mask (derived). Tracing uses the signed distance, not its absolute value, with hits below 0.01 px; the returned hit distance is never read. With `SKY_INTEGRAL 1` the top cascade sums four bin averages without dividing by 4, four times too bright (derived); the sky constants and the division by 6 match XffcD7. `PIXEL_PERFECT 1` outputs the nearest probe's 4 directions with no 2π; the bilinear path is inactive. `MODIFIED_INTERVAL_SCALING 1` gives cascade 0 a zero-length interval and leaves a gap between cascades 1 and 2, at `[0.5, 3.5]` and `[4.5, 16.5]` scaled base lengths (derived). Against MfXyRj: the circle moves into `circle_intersect` with the probe as origin, so its clamp `max(t, t_start)` compares distances in one frame; variant 1 drops the circle; the midpoint mode loses its midpoint and weights; the top-cascade guard that blacked out unused texels is gone; it inherits `intersect()` without the clip offset and the hit test without a minimum `t`. Unused: `RAYS_FORK_POW`, `roundSDim`, `c0_pixels_count`, the hit distance, and the keyboard and Buffer B channels of Image.

## Independent codes

- **3cKczD** (youssef_afella, 2025-11-30). Direction-major, one level per pass: Buffer A computes level 4, B level 3, C level 2, D level 1 and Image level 0, each reading only the level above from the same frame, so the whole chain runs in one frame. The work area is the resolution rounded down to multiples of 16; level `n` has `2^n × 2^n` blocks, one per stored bin, probes at `(i + 0.5)·2^n` px, and each probe traces 4 rays at `(4b + i + 0.5)·2π/4^(n+1)` and stores their mean, so every level traces four rays per pixel. Intervals `(4^n − 1)·⅔` to `(4^(n+1) − 1)·⅔` px with 0.3333 for 1/3: `[0, 2], [2, 10], [10, 42], [42, 170], [170, 681.9]`. Missed rays read the parent bin once with hardware bilinear filtering at `0.5·x + 0.25`, clamped inside the parent block, then `rgb += a·parent.rgb` and `a *= parent.a`. Scene: ten concentric ring arcs with moving apertures and rotations, even rings coloured emitters and odd ones black occluders, plus two black arcs; 32 sphere-tracing steps to 0.001 px; misses and step exhaustion return `(0, 0, 0, 1)`; no sky, tone map or colour conversion. Read from the code: pixels outside the work area return alpha 0, an opaque black object, so a 1920×1080 frame has 8 black rows at the bottom; the clamp shifts samples at block edges by up to a quarter texel.
- **tf2XRc** (SJarod, 2025-03-19, "for research", citing a paper and two web pages). Three cascades on 16×16, 8×8 and 4×4 UV grids with 8, 16 and 32 directions at `(k + 0.5)·2π/q`; Buffer C stores descriptors and probe positions, Buffer D traces every interval in one pass (row per cascade, column `probe·q + direction`). Intervals `[0, 1], [1, 3], [2, 6]·20/256` UV, overlapping on `[2, 3]` where contiguous ones would put cascade 2 at `[3, 7]`. Each ray takes 17 texel reads `len/16` apart from a slightly offset start and stops at alpha ≥ 0.5, with no distance field; lights emit and block, a black mouse disc only blocks. Buffer B composites, per pixel and per finest direction, cascades 0 to 2 at index `i/2^(2−j)`, each blended over four probes, front to back (`sum += T·rgb`, `T *= a`), which unrolls the merge over the cascades: 960 fetches per pixel divided by 32, with no pre-averaging, fix, sky, 2π or tone map. Buffer B runs before C and D and reads them a frame late (inference); nothing accumulates over frames. Read from the code: cascade 0 needs 2048 columns, so narrower canvases lose the last probes (240 to 255 at 1920 px); unclamped indices extrapolate border cells with negative weights and zero alpha, darkening them; probes, steps and directions live in UV, so directions are uneven in pixels on non-square canvases; direct light is added twice on lights and occluder; storing the interval count in alpha failed because Shadertoy forces alpha to 1.
- **w3XSz4** (Neylick, 2025-04-26, a learning build crediting fad, Xor, Maxdev and jason.today; the header warns of bugs and high cost). Branching factor 2: eleven cascades in one 1024² cube map, all computed per frame reading last frame's cascade above, about 10 frames to settle (inference); cascade 0 gets half of the `6·1024²` texels and cascade `n` `c0 >> n`, with `floor(1773/2^(n+1))` probes per side (886 to 1, then 0) and `4·2^n` directions. Intervals doubling from `[0, 2b]` with `b = √2` px (`BASE_LENGTH` 1/1024 of the cube's diagonal, not the viewport's) to `[1448, 2896]` px. Up to 16 steps each at most a sixteenth of the interval; hits within 0.1 px return colour decoded with 2.2; five analytic emitters, no direct light; fad's sky divided by 6 and scaled by 20 before decoding. Two child directions are each blended over four upper probes, summed, divided by 4, then `near + near.a·far`; the gather is bilinear over four cascade 0 probes, the mean of 4 directions, with a 1/2.2 encode and no tone map. Its occlusion-breaking defects are in [artifacts and fixes](artifacts_and_fixes.md#recurring-implementation-bugs); also: cascade 10 has 0 probes per side, so its pass divides by zero; cascade 9's directions from 1536 up read the magenta fill of the unused tail, the gather places probe `k` at `k/side`, half a cell off, the sky's ×20 before the 2.2 power is about 728× in linear terms, and the header's 16 directions do not match the code's 4.

- **4clcWn** (Mytino, 2024-07-15) draws two cascades' rays with the bilinear and forking fixes switchable ([artifacts and fixes](artifacts_and_fixes.md#cheaper-fixes)); with both off it shows plain RC.
- **XcfyDj** (mxcop, 2024-07-21, the site's "Parallel fix" and the wiki's "Parallax fix"; the author says the diagram may be wrong and asks how to draw the fix). Two cascades: cascade 0 with 8×8 probes `C = 0.1·H` apart and 4 directions over `[0, 0.5C]`, cascade 1 with 4×4 and 16 over `[0.5C, 2C]`. For each cascade 0 ray ending at `E`, the upper probe `U` is the coarse cell containing the probe, and the reprojected direction `normalize(E − U)` is the direction in which `U` sees the lower ray's end, the per-upper-probe lookup of the parallax fix. `FORKING_FIX_ENABLED` moves the start; `BILINEAR_FIX_ENABLED` and `REPROJ_FIX_ENABLED` feed variables nothing reads, so the reprojection arrow is always drawn and the bilinear fix never; `CIRCLE_PROJECTION_FIX_ENABLED` takes the far root with no discriminant check, and since the nearest upper probe is `0.707·C` away against a radius of `0.5·C`, two of every probe's four directions take the root of a negative number (derived). Its ringing testbed's radiance array is set to 100 and never written, so its fluence is constant.
- **cslSW4** (FatalSleep, 2022-11-19), linked by GM Shaders as its author's bilinear example and ten months older than fad's, is a general interpolation demo: corner samples every 50 px from a four-colour gradient, blended correctly left of the mouse and by screen-wide UV with two corners swapped on the right, which steps at every cell edge; with no mouse input the right branch fills the screen. RC probes sit at cell centres, so the RC merge needs the half-cell offset `q = round(pf) − 1`, `w = pf − q − 0.5`.
- **NttSW7** (Mathis, 2021-12-16), the source of the sky integral every fad-lineage shader carries, solves 2D direct light exactly with nothing sampled. Six draggable segments (a floor, a wall, two ceilings, a wall rotating at 2 rad/s about its midpoint, and an emitter) live in Buffer A; R resets and A pauses. Per pixel, each segment starts as one visible part and is clipped against every other, giving exact visibility; each visible part becomes an angular span by `atan2`, and `L(P) = max(0, [Sky(0, 2π) − Σ_visible Sky(span) + Σ_emissive E·width]/2π)`. The sky and sun integrals and their constants are in [core theory](core_theory.md#colour-space-and-range); EmissiveColor is `4·(1, 0.9, 0.9)`. Over the full circle the sky gives `2π·SkyColor` and the sun about `0.381·SunColor`, slightly below the untruncated `π/√S = 0.393` because the tail is cut at 0 and 2π, so an unoccluded pixel shows about `(0.807, 0.925, 1.061)` before tone mapping (derived). NttSW7 divides the full-circle integral by 2π where the RC shaders divide by 6. Walls reflect nothing, so the image is direct light only, though the header calls it single-bounce; segments have no thickness and must not intersect; a scatter version in a block comment was dropped for compiling too slowly. Tone map `1 − exp(−1.2·C)`, then a power of 0.45.

## Media

- **wfyyDz** (codyjbennett, 2025-12-01). Six levels with spacing `2^c` px, `4^c` directions (level 0 one direction pointing left), intervals `0.2·[4^c, 4^(c+1)]` px; each probe owns a `2^c × 2^c` block. Casts take `16·2^c` evenly spaced samples, each adding `rgb·T·a` and multiplying `T` by `1 − a`, so opacity is per sample ([2D implementations](2d_implementations.md#scene-representations)). The bilinear fix casts from `probe + dir·start` to `upper_b + dir·end` for each of four upper probes, reads that probe's four child directions, merges, weights bilinearly and averages. Three moving emitters and absorbers, drawn at twice their radius; no sky. The accumulator starts at alpha 1, so stored alpha is not a transmittance below the top, though the displayed colour does not depend on it. Buffers A to C compute levels 5/4/3 on even frames and 2/1/0 on odd frames, refreshing the chain every two frames; output exposure ×2, ACES fit, sRGB. The author calls the bilinear fix a nonphysical trick that hides ringing and suggests HRC for sharp shadow edges. Its hand-written four-probe blend exists because float linear filtering is unreliable on some targets.
- **ffl3Rf** (codyjbennett, 2026-03-10). wfyyDz's passes, schedule, intervals with `16 << c` steps, scene and image pass in a direction-major layout: each upper direction `4·dir + i` is one `texture()` read, which the comment calls a bilinear sampler, clamped to the upper grid, and the four are averaged; the description still advertises volumetrics and a bilinear fix it lacks. `texture()` takes its mip from derivatives that jump at tile boundaries, which NfySzt fixes with `textureLod` (inference; the channel's mip setting is not in the code). Shared with wfyyDz, read from the code: the disc test `distance − r < r` draws discs at twice their radius; 1% per sample, an optical depth of about 0.20 per pixel at level 0 and 0.008 at level 5, a factor of about 24 (derived); samples at step starts, so interval ends are never sampled; probes misplaced by up to about 24 px at level 4 of 1280×720 on resolutions not divisible by the spacing.
- **NfySzt** (codyjbennett, 2026-09-01), labelled elsewhere as a refraction fix though it has no refraction or angle correction. It keeps the parent's passes, schedule, constants, intervals, direction-major tiles and four-direction hardware fetch (now `textureLod` at level 0, clamped inside the tile), and replaces the marched scene with an opaque blocker of radius 50 and one pulsing emitter, intersected analytically per ray at their nominal radius (half the drawn size of the parent's discs) and clipped to the interval. Blocker hits store 0 and skip the merge, emitter hits return 1, and misses add a quarter of the sum of four upper directions, with no bilinear fix; with binary hits this equals the parent's merge (derived). The level-5 sky branch is empty and alpha fixed at 1; positions through `probeUV·resolution` keep levels aligned but stretch them in pixels.

## Extended gathering

**NfVXRc** (Suslik, 2026-09-01) and **sfVSzd** (2026-09-02) fork 4ctXD8 with one live cascade of 512 probes across, spaced `W/512`, with 8 directions at `(k + 0.5)·45°`. Nothing merges: `MergeIntervals` is never called and three of the six listed `MERGE_FIX` modes change no code. NfVXRc traces `[0.12·W, 0.18·W]` (scale `(80, 120)` times `0.0015·W`) and gathers 200 directions per pixel (8 while the mouse is held): each direction's sample point lies 120 px from the pixel, and for the two stored directions bracketing it the source probe sits at the sample point minus that direction times 120 px, read bilinearly from four probes and weighted linearly between the two directions; the fixed 120 px matches the trace end only at about 667 px width. sfVSzd traces `[0.075·W, 0.18·W]` on even frames and on odd frames replaces each texel by 200 samples over one direction spacing on each side, with source probes on circles of radius `0.18·W`; a final pass sums the 8 directions over four bilinear probes, the mouse state chooses whether trace-only or gathered frames show, and the ring gather declares a shadowing `probe_location` that leaves a cascade index uninitialized. In both, `MERGE_FIX 3` returns zero for starts inside shapes, the parallax modes only stretch the trace end by 1.1, `intersect()` drops the clip offset and the sky is never called. The method is discussed in [light transport alternatives](light_transport_alternatives.md).

## Cascades for gravity

**XcB3Ry** and **MfS3Wm** (Suslik, 2024-01) run a gravitational fluid simulation that uses the cascade hierarchy for an N-body field, naming mlSfRD as the RC reference. One viewport texture holds matter (impulse, density, colour) on the left and acceleration on the right, each as cascades of `(W/2 >> k) × (H/2 >> k)` cells stacked vertically.

- XcB3Ry (six cascades, factor 4): level `k` of matter is the 2×2 average of level `k − 1`; level `k` of gravity sums `density·4^k·Δ/|Δ|³` (Newton with `G = 1`, no softening) over sources at distances in `((4^(k−1) or 0) + 1, 4^k + 1)·5.1` base pixels, with linear fades of width `2·(2^k, 2^(k+1))` at both band edges, then adds the bilinear sample of level `k + 1` from the previous frame, the RC merge, so each level holds its band plus everything coarser and far fields arrive over frames. Matter advects by scattering each source within radius 10 to its moved position with tent weights, conserving mass and momentum but not energy. The mouse adds mass and impulse; space or the first ten frames reseed about 250 orbiting blobs.
- MfS3Wm, the earlier version: seven cascades at factor 2 with base distance 15, hard bands `[2^(k−1), 2^k)·15` and the coarser-level accumulation commented out, so each level holds only its band.
- The scheme carries over to any long-range field whose needed resolution falls with distance.

## Shaders that are not RC

Several of these are linked in community lists with descriptions their code does not match; the descriptions below are from the code.

- **McSyWm** (Suslik, 2024-07-31): two cosine-driven colours alternating in rows (a checkerboard with `USE_CHECKERBOARD 1`), averaged on sRGB values (black and white give 0.5, 128 of 255) and on linear values re-encoded (0.730, 186 of 255); the author asks why the checkerboard looks worse than lines. The rule it shows, average linear radiance, is in [core theory](core_theory.md#colour-space-and-range).
- **3tdSDj** (iq, 2020-02-15, MIT): `udSegment`, `h = clamp(dot(pa, ba)/dot(ba, ba), 0, 1)` and distance `|pa − h·ba|`; the demo subtracts a breathing radius to make a capsule and rings the distance around the mouse. RC copies (tmpvar's fluence debug view) call it `sdSegment` though it is unsigned.
- **fld3R4** (paniq, 2021-11-01), labelled elsewhere as a frustum sweep with angular falloff and Gaussian penumbras, is a 2D light propagation volume with none of those. Each pixel holds order-1 circular harmonics (two directional terms and a constant, basis `√((2, 2, 1)/2π)`), one buffer per colour channel. Each frame a cell gathers from its four neighbours through three lobes each: one along the face normal with solid angle `acos(3/5) ≈ 53.13°` and two tilted ones of `acos(3/√10) ≈ 18.43°`, summing to 90° per neighbour, 12 terms. Per lobe, the arriving light `L` and the neighbour's occupancy `E` (from an SDF-derived opacity, 0.5 on the surface) give `L·(1 − min(E, 1))` plus a reflection `min(E, 1)·L·albedo`, or `albedo·E` for emitters at a surface. Light moves one cell per frame through each buffer's previous frame, so it needs many frames to cross the screen. The inputs are declared 8-bit, which would clip negative harmonics and the emitters' 20× radiance if that is the storage format. A strip on the right ray-marches a rotated 1D view; output ACES fit and exact sRGB. LPVs in general are in [related probe GI](related_probe_gi.md).
- **7c2XDw** (Suslik, 2026-04-22) and **7f2SzV** (2026-04-24), linked elsewhere for angular falloff and Gaussian penumbras, have neither. 7c2XDw moves a scan column one pixel per frame; two carrier columns move one row up and one down per frame from each single-pixel source, crossing the scan at 45°, and an accumulator writes the column into the image: a 90° wedge per source, with no cascades or per-level occluder counts, and negative values painted red as a check. 7f2SzV diffuses light one column per frame, replacing each non-source pixel by the mean of three taps one column to the left at offsets `−δ, 0, +δ` rows with `δ = 2·mouse.y/H` (0 until the mouse moves), spreading light right in a cone of half-angle `atan δ` through a gap in a wall; the box kernel repeated over columns approaches a Gaussian, but the code has no Gaussian term. Sweeping methods are in [light transport alternatives](light_transport_alternatives.md).
- **XXVfW3** (fb01, 2025-02-04, tagged radiancecascade): no cascades, probes, intervals or merge; one pass simulates 27 shapes (balls, blocks, triangles, ovals) on triangle-wave paths with three collision passes recomputed in every pixel, and each pixel averages 50 rays sphere-traced for at most six steps up to `t = 4`, misses black, ACES fit, no state and no lag.
- **MsV3zR** (FabriceNeyret2, 2016-01-18, "pyramid op"): a pyramid of 2×2 maxima of the webcam image in one buffer, one level per frame, dividing the image by the top value to normalize brightness; it shares only the level stack with RC.
- **sXcGRB** (SpinningCube, 2026-09-16), linked elsewhere for isometric terrain, has no isometric view: for each heightmap pixel a row scan stores the steepest slope toward +x and −x (`O(W)` per pixel, cached until the resolution changes); the sun moves overhead along x as a 0.2 rad disc, visibility is the disc's visible fraction above each horizon from the area of a circular segment, combined as east plus west minus one; ambient occlusion `0.5 + 0.5·cos(atan(east) + atan(west))` is blended in at 1%; there is no horizon along y. Horizon methods are in [related screen-space GI](related_screen_space_gi.md).
- **XXXyWM** (https://www.shadertoy.com/view/XXXyWM), linked as a line-sweep demo, returns Shadertoy's not-found page (checked 2026-10-19): deleted, private, or a wrong ID.

## Connections

- **Names outlive meanings.** The 4ctXD8 framework's names (`MERGE_FIX`, `BRANCHING_FACTOR`, `SPATIAL_SCALE_FACTOR`, `C_MINUS1_GATHERING`, the `CastMergedInterval*` family, `MergeIntervals`) and its dead code (`RAYS_FORK_POW`, `roundSDim`) run through every descendant ([history](history_and_landscape.md#first-public-implementations-and-the-shadertoy-lineage)), while the same `MERGE_FIX` number selects different code in 4ctXD8, MfXyRj, lcfcR2 and NfVXRc, and lcfcR2's "mask fix" is a hashed pick. A fix is identified by its code, not by its switch value or title.
- **Descriptions outside the code are unreliable.** fld3R4, 7c2XDw, 7f2SzV, sXcGRB and NfySzt are described in link lists as things their code is not, ffl3Rf's own description advertises a fix it lacks, and XXVfW3 is tagged RC with no cascades. Only read code supports a claim about a shader.
- **The lag is the host's.** 3cKczD runs a five-level chain inside one Shadertoy frame by giving each level its own pass, so the frame lags of mtlBzX, w3XSz4 and the buffer rings come from packing cascades into one cube-map pass, not from the method (inference).
- **Unguarded geometry recurs.** XcfyDj's and lcfcR2's circle roots, MfXyRj's discriminant on tall views, the clip offset dropped in four shaders and missing minimum `t` are the same class of bug in [artifacts and fixes](artifacts_and_fixes.md#recurring-implementation-bugs).
- **Two output conventions.** The fad line's ×2π fluence and the testbed line's mean radiance under one tone map make side-by-side screenshots differ by about 2π in exposure (derived), which matters when comparing fixes across forks.

## Single-frame assessment

For single-frame 3D RC (inference, from the shaders above): the testbed line's bilinear fix, `C_MINUS1_GATHERING` and the one-pass-per-level schedule of 3cKczD are the parts that transfer; the cube-map packing that forces one level per frame does not. Volumetric marches must scale opacity by step length before their results can be compared across cascades (wfyyDz, ffl3Rf). tf2XRc's per-pixel composite of every cascade shows that the merge can be unrolled at gather time, at 960 fetches per pixel for three 2D cascades, which grows too fast for 3D (derived from its counts).
